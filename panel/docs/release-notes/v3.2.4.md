## 版本概览

`v3.2.4` 收的是两个 issue：

- [#117](https://github.com/linzixuanzz/daidai-panel/issues/117)：**定时任务页点「最后运行」排序，已禁用的任务跑到了最上面。**
- [#116](https://github.com/linzixuanzz/daidai-panel/issues/116)：v3.2.2 编辑器双引擎上线后的实测反馈，一共 6 项 —— 其中 1 项是确认的真缺陷（桌面端缩进参考线间隔「F5 刷新会随机在 2 和 4 之间切换」），其余 5 项是功能诉求。

两个 issue 里点名的每一条都做了，没有挑着做。

## 升级须知

### 1. 「显示空白符」的默认值变了：从「关闭」改成「仅选中」

#116 的报告者说得很清楚：

> 显示空白符功能其实我指的是选中的空白符用小圆点显示，但是我没表达清楚

v3.2.2 把这一项做成了「开 / 关」二态，开就是**一直**画灰点 —— 那确实不是他要的。本版改成三档（**仅选中 / 始终 / 关闭**），并且**默认档从「关闭」改成「仅选中」**：只有被选中的空白才画灰点和箭头。这也是 VS Code / Monaco 的原生默认。

所以升级后第一次选中一段代码，会看到以前没有的灰点。不想要就在齿轮菜单里把「显示空白符」点到「关闭」。

> 已经在 v3.2.2 里显式开过这个开关的用户不受影响：老值 `on` 映射成「始终」、`off` 映射成「关闭」，你的选择原样保留。

### 2. CodeMirror 引擎下不再有代码缩略图

原文是：

> 代码缩略图在移动端的作用并不大，因为移动端本身屏幕小，缩略图看不到什么内容还占用了部分显示区域……可以适当做减法，去掉 CodeMirror 的代码缩略图。

**采纳了。** v3.2.2 那份自研缩略图（`utils/codeMinimap.ts`，265 行）整个删掉了，齿轮菜单里的「代码缩略图」这一项现在**只在 Monaco 引擎下出现**。

坦白说一句：v3.2.2 的发布说明把这个缩略图当作卖点，还专门用了一节论证「为什么自己写而不是引第三方包」。两版之内先加后删，理由是实测下来它在移动端不划算 —— 它硬占正文右侧 **64px**，手机 360px 宽的编辑器上就是 **18%** 的正文宽度，而移动端上下滑动本来就比滚轮快、缩略图的拖动价值被大幅削弱。

**桌面端一点没少**：桌面的自动档解析出来本来就是 Monaco，用的是 Monaco 原生缩略图（点击、拖动视口框都正常），这一版对它没有任何改动。真正受影响的只有「桌面端主动把引擎切成 CodeMirror」的人，他们随时可以切回 Monaco。

### 3. 编辑器偏好现在跟着账号走，不再只存在浏览器里

原文：

> 代码缩略图、缩进参考线、显示空白符可以设置默认状态，这样即时切换到不同的设备或切换到不同的 IP 地址仍然能保留使用偏好

本版新增一张 **`user_preferences` 表**（按用户一行）和一对接口 `GET / PUT /api/auth/preferences`，把 **5 项**编辑器偏好落到服务端：自动换行、代码缩略图、缩进参考线、显示空白符、缩进宽度。换设备、换浏览器、换 IP，登进来还是这一份。

**为什么是 per-user 表而不是复用现有的系统配置**：面板已有的 `system_configs` 是**全面板一份**的全局键值表，A 改了 B 会跟着变；而且它的读写接口 `/api/configs` 是**管理员独占**的，而脚本页 `operator` 角色就能进 —— 复用它会让非管理员用户点一下开关就 403。编辑器开关是纯个人习惯，就该按人存。

**唯一刻意不同步的是「编辑器引擎」那一项**（自动 / CodeMirror / Monaco）。它带着 `auto` 的设备自适应语义：触摸设备与窄屏会硬回落 CodeMirror。把你在桌面上显式选的 Monaco 同步到手机，等于把手机用户锁死在一个用不了「长按出系统菜单 / 双击出选择手柄 / 按住拖光标」的引擎上。**引擎跟设备走，偏好跟人走。** 这一点也和报告者自己的判断一致：

> 两端自动匹配固定的编辑器是合理的，不需要更改自动默认配置

**老用户的本地偏好不会丢**：升级后第一次打开编辑器，面板发现服务端还没有你的记录，会把**本机现有的那份偏好上行迁移**上去，而不是拿一套默认值把本机覆盖掉。（接口为此专门下发了一个 `stored` 字段来区分「我没有你的记录」和「你主动选了默认值」—— 少了这个字段，这两种情况的响应体逐字相同，客户端没法判断。）

### 4. 数据库加了一张表

`user_preferences`（`id / user_id / editor / created_at / updated_at`），由面板启动时**自动建出来**，存量数据平滑升级、无需任何手工操作。备份归档里也一并带上了它。

### 5. 接口变化（都只增不改）

| 变化 | 说明 |
|---|---|
| 新增 `GET /api/auth/preferences` | 读当前登录用户的编辑器偏好。只要登录就能读，**不限角色** |
| 新增 `PUT /api/auth/preferences` | 写。**字段级合并**，只提交要改的键，两个标签页各改各的开关不会互相覆盖 |
| `GET /api/tasks` 的 `sort_rules` 语义 | 见下面「修复 1」，展示顺序会变 |

API 文档已同步。

## 修复 1：按列排序时，已禁用的任务不再冒到最上面（#117）

原文：

> 定时任务页点击 最后运行 会发现已经禁用的到最上面来了，应该把禁用的任务放在下面，然后分区排序。状态空闲 运行中 的都在上边，禁用的在最下边

### 为什么会这样

面板的任务列表有**两条**排序路径：

- **默认排序**（不点表头、不用视图排序）走 SQL，口径是 `置顶 → 状态分组 → 拖拽顺序 → 开机执行顺序 → 创建时间`。它**本来就是分区的**，所以默认视图下没人报这个问题。
- **按列排序 / 视图自带排序**走内存排序。这条路径的比较器里**只有排序规则，没有任何分区判断** —— 状态分组那两层被埋在「所有规则都平手才回落」的兜底里。

于是只要一条禁用任务的「最后运行」有值，它就完全按时间和启用任务混排，降序时最近跑过的禁用任务直接冒到第一行。

**「下次运行」那一列碰巧看不出来**：面板只给「非禁用 + 定时类型 + 表达式非空」的任务现算下次运行时间，禁用任务恒为空，被「空值排最后」这条规则顺手扫到了底部。也就是说它满足用户诉求纯属巧合，「最后运行」不满足。

### 改成什么

把**置顶**和**状态分组**这两层提到所有排序规则**之上**：分区是骨架，排序规则只决定区内顺序。口径直接复用面板里已有的那一份（启用 / 排队中 / 运行中 = 第一区，已禁用 = 第二区），不另写一套。

置顶也一起前置，是为了和默认排序保持一致 —— 否则会出现「默认排序时置顶的禁用任务在最上、点一下最后运行它掉到最下」的自相矛盾。

**一个例外：按「状态」排序时不分区。** 视图的排序字段里有「状态」，而状态分区本身就是按状态分的，用状态排序时再分一次是自相矛盾：会让一个标着「升序」的视图读出 `排队中 → 空闲中 → 运行中 → 已禁用` 这样的非单调顺序，而且升序降序对禁用任务完全失效。所以当排序规则的**第一条**是「状态」时，状态分区让位给规则本身（置顶分区仍然生效）。

**影响面**：`name` / `created_at` 这类字段也从「全局排序」变成了「分区内排序」—— 比如「创建时间（最新优先）」不再把全场最新的那条放第一行，如果它是禁用的。这是 #117 有意要的效果，API 文档里的 `sort_rules` 描述已经跟着改了。

## 修复 2：桌面端缩进参考线间隔不再随刷新在 2 和 4 之间乱跳（#116-1）

原文：

> 缩进参考线有一个BUG，参考线间隔（change tab display size）开始是4，但是F5刷新会随机在2和4之间切换。

**根因已坐实**，是两条路径叠在一起：

1. **Monaco 的 `detectIndentation` 默认是开的，而且只在建 model 那一瞬间按内容猜一次。** 面板给了 `tabSize: 2`，但那只是「猜不出来时的兜底」，真正生效的是猜出来的值；`setValue()` **永远不会重猜**。
2. **脚本页是「先把编辑器挂上、再 `await` 拉文件内容」。** 于是「Monaco 那个 MB 级 chunk 的动态加载」和「文件内容接口」两个异步谁先到，就决定了它猜的是**空串**（→ 兜底 2）还是**真实的 4 空格脚本**（→ 4）。冷热缓存、网络抖动都会翻转结果，而且编辑器挂上之后不会因为切文件而重建，所以这一次猜的结果在整个会话里被冻住 —— 与「刷新一次定一次」的观感完全吻合。

还有一条次级路径：Monaco 内部有个缓存键不一致的问题，会让**任何**一次带 `wordWrap` / `renderWhitespace` 的选项更新触发一次重猜 —— 也就是说你手动用 Monaco 自带的 `Change Tab Display Size` 选了 4，随手切一下「自动换行」它就被抹回去了。

**改法**：显式关掉 Monaco 的自动检测，缩进宽度由面板自己算、自己给。两条路径同时消失。

> 实测：同一个 4 空格 Python 脚本连刷 **20 次**，参考线间隔 20 次全部稳定在 4 列（改动前正是这里随机跳）。

## 新增 1：缩进宽度可以设了 —— 自动检测 / 2 / 4 / 6 / 8（#116-3）

原文：

> 参考线可以设置默认间隔值，如2 4 6 8....或者自动从内容中检测缩进

两个都做了，做成一个五档循环项：**自动检测 / 2 / 4 / 6 / 8**，默认「自动检测」。

「自动检测」不再依赖 Monaco 那个「建 model 瞬间碰运气」的行为，而是面板自己扫文件内容算（扫描有行数上限，超长文件不会拖慢打开），**两个引擎共用同一份判断**，所以 CodeMirror 和 Monaco 上看到的间隔是一致的。切换文件会重新检测一次。

顺带把 CodeMirror 侧也接上了：在此之前它的缩进宽度是**写死 2**、根本改不了。

> 实测：4 空格的 Python 脚本 → 4 列，2 空格的 JS → 2 列，来回切文件 5 轮次次正确；手动拨到 2 / 4 / 6 / 8，参考线间距依次是 15 / 31 / 46 / 62 px，成比例。

## 新增 2：显示空白符改成三档（#116-4）

原文：

> 这个功能可以改为选中的空白符总是显示小圆点+显示空白符开关……或者是三种状态切换 a. 选中的空白符显示小圆点 b.一直显示小圆点 c.总不显示

做成三档循环：**仅选中 / 始终 / 关闭**，默认「仅选中」（见上面「升级须知 1」）。

Monaco 侧原生就支持这三档，直接透传。**CodeMirror 侧的「仅选中」是自己写的** —— CodeMirror 内置的 `highlightWhitespace()` 是无参的全量装饰，没有这一档。新写的这个扩展复用了内置的那两个 class，所以灰点和箭头的样式与「始终」档逐像素一致，一行 CSS 都没改。

> 实测（CodeMirror）：「仅选中」档下不选中时 0 个标记、选中 4 行后 15 个；「始终」档下不选中也有 47 个；「关闭」档下选中也是 0 个。Monaco 侧同样三档正确。

## 新增 3：注释改回常规体（#116-6）

原文：

> 最后能不能把注释文字的斜体(italic)改回之前的常规体

改了。顺便说清这个「之前」是什么时候：v3.2.0 之前面板用的是 Monaco 内置主题，注释**不是**斜体；v3.2.0 换 CodeMirror 时新写的高亮表里加了 `fontStyle: 'italic'`，v3.2.2 上 Monaco 双引擎时又把它同步到了 Monaco 侧。这一版把这两处都删了，两个引擎、明暗两套配色一起恢复常规体。

**Markdown 的 `*强调*` 仍然是斜体** —— 那是内容语义（源文本本来就该斜体），和「注释用斜体」这种主题偏好是两回事，没有连坐。

## 关于「两个编辑器应该互补而不是功能相同」

原文：

> 我觉得这两个编辑器的功能应该是互补，而不是做到拥有相同功能。Monaco在桌面端更加成熟，CodeMirror则更适配移动端(触屏设备)，两端自动匹配固定的编辑器是合理的，不需要更改自动默认配置。

**这个判断被采纳成了本版的取舍原则**，具体落在三处：

- **自动分配引擎的规则一个字没改**：触摸设备与窄屏仍然硬回落 CodeMirror，桌面仍然是 Monaco。
- **缩略图不再强求两边一致** —— 它现在是 Monaco 独有的能力，CodeMirror 下菜单里根本不出现这一项（而不是留一个点了没反应的开关）。
- **引擎选择不参与跨设备同步**，理由见上面「升级须知 3」。

## 验证到什么程度

- 后端 `go test ./... -count=1`：**11 个包全绿**。新增偏好接口的测试文件，并给任务排序补了回归用例，其中钉死的关键行为包括：
  - 按「最后运行」升序 / 降序，禁用任务**两个方向都**在所有启用任务之后（改动前这条必然失败）；
  - 置顶任务（哪怕它是禁用的、哪怕最后运行时间最旧）仍在最前；
  - 启用任务组内仍按规则排序、空值仍沉到**本组**末尾 —— 分区没有把原有语义吃掉；
  - 按「状态」升序 / 降序时状态分区豁免，读出来是 `0 → 0.5 → 1 → 2`；状态作为**第二**条规则时分区仍然生效；
  - 偏好接口：新用户拿到默认值、字段级合并成立、非法枚举回 400 且一条都不落库、两个用户互不影响、脏 JSON 回落默认值而不是 500、`stored` 在「无记录 / 空串 / 脏 JSON」三种情况下都是 false。
- 前端 `npm run build`（含 `vue-tsc`）通过。
- **起了一套真实实例，用 Chrome 逐项实测**（不是只看代码）：
  - #117：造出「禁用 + 最后运行时间是全场最新」的任务，接口层与页面层各验一遍升序降序，禁用的都在最后、置顶的都在最前；
  - 缩进宽度：同一脚本连刷 20 次全部稳定在 4 列；手动拨 2 / 4 / 6 / 8 参考线间距成比例；两个引擎切文件都会重新检测；
  - 缩略图：切到 CodeMirror 后菜单里没有这一项、正文右侧那 64px 也拿回来了，切回 Monaco 菜单项和缩略图都回来；
  - 空白符：两个引擎各验三档；
  - 注释：两个引擎下 `font-style` 都是 `normal`；
  - 跨设备：在菜单里把三项改成非默认值 → 确认服务端已存 → **清空整个 localStorage 再刷新** → 三项原样回来，菜单、状态条、Monaco 缩略图全部对得上；
  - 权限：用一个 `operator` 角色的账号验证它能读写自己那份偏好（这正是不复用管理员独占的 `/api/configs` 的原因）。
- 改动落地后又做了一轮**多维度对抗性代码审查**，确认并修掉了 8 个问题，其中值得单独提的三个：
  - 升级路径上老用户本地偏好会被服务端默认值冲掉（就是上面 `stored` 字段的由来）；
  - 慢网下首屏那次拉取会把「拉取途中用户刚点的开关」顶回旧值；
  - Monaco 的 `tabSize` 是**全进程共享**的配置，一开调试弹窗就会把主编辑器的缩进宽度带偏。

## 本版没做的

- **没有**改动自动分配引擎的判据（触摸 / 窄屏 → CodeMirror，桌面 → Monaco），这是报告者明确说「不需要更改」的部分。
- **没有**把编辑器引擎选择同步到服务端（理由见「升级须知 3」）。
- **没有**给暗色主题等其它本机偏好做跨设备同步 —— 本版只处理 #116 点名的编辑器这一组。
- **没有**保留 CodeMirror 侧的缩略图（删除而不是修复，理由见「升级须知 2」）。
- **没有**暴露 Monaco 空白符的另外两档（`boundary` / `trailing`）：CodeMirror 侧没有对应物，暴露出来只会多造一处引擎间行为差异。
- **没有**改动 Magisk 模块外壳脚本、Docker entrypoint、Dockerfile 与 `docker/nginx.conf`。

## 关于 APP

本版**没有** APP 侧改动，APP 不需要跟随升级。

接口面的变化对 APP 是安全的：

- 新增的 `GET / PUT /api/auth/preferences` 是**纯网页端**的编辑器偏好，APP 不调就完全不受影响。
- `GET /api/tasks` 的**响应结构没变**，变的是带 `sort_rules` 时的**展示顺序**（置顶与状态分组现在压在排序规则之上）。如果 APP 有按列排序的入口，升级后已禁用的任务会沉到列表末尾 —— 这正是 #117 要的效果。API 文档已同步。

## 升级方式

| 部署方式 | 操作 |
|---|---|
| Docker | 重新拉取镜像后重建容器（本版没有改动 entrypoint 与 Dockerfile） |
| Magisk 模块 | 面板内一键更新即可（本版**没有改动模块外壳脚本，不需要重刷 ZIP**） |
| 裸机 / Windows | 面板内一键更新，或下载新版二进制替换 |

本版新增了 `user_preferences` 表，由面板启动时**自动建出来**，存量数据平滑升级，无需任何手工操作。

**升级后值得看一眼的地方**：打开脚本管理，点一下工具栏上的齿轮 —— 「缩进宽度」和「显示空白符」是本版新增/改档的两项，默认分别是「自动」和「仅选中」。改好之后换台设备登进来，它们还在。

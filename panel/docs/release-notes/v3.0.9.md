## 版本概览

`v3.0.9` 是一个**用户反馈驱动**的版本，两条线：

- **界面优化**：[#103](https://github.com/linzixuanzz/daidai-panel/issues/103) 提的 11 条建议全部落地，集中在「列表页怎么用起来更顺手」——批量操作栏不再把工具栏顶成两行、视图分组栏与状态筛选栏样式统一、任务名后的标签可以按类别隐藏、实时日志提到一级按钮、编辑器加自动换行开关、脚本目录树可收起。
- **缺陷修复**：手动创建的任务被误加「已锁定」标签。

感谢 [@hlt1995](https://github.com/hlt1995) 的详细建议和录屏。

## 优化：批量操作栏不再把工具栏顶高（#103）

原来勾选任务后，那一排批量按钮会**凭空插进工具栏右区**。实测（1600×900，定时任务页）：

| | 勾选前 | 勾选后 |
|---|---|---|
| 工具栏高度 | 39px | **83px** |
| 表格位置 | — | **整体下移 44px** |
| 右区与状态筛选栏的中心线 | 对齐 | **错位 22px** |

搜索框被挤到第二行，整页跟着往下跳一下。

现在改成**左槽内容切换**：勾选时批量栏占据原本筛选区的位置，筛选区让位；取消勾选再换回来。工具栏高度**始终是 39px**，表格纹丝不动。

配套调整：

- **按钮尺寸统一成 32px**。原来批量按钮是 24px，而同一排的排序 / 更多 / 新建按钮和搜索框都是 32px —— 现在严格等高。
- **「批量禁用」标红**（描边），与实心红的「批量删除」之间隔开若干中性按钮，避免两个红按钮挨在一起被误点。
- **补上「已选 N 项」计数与「取消选择」按钮**。筛选区被藏起来之后，这是退出多选状态的出口。
- **窄屏自动收字**。14 寸笔记本 150% 缩放（等效 1280×720）下，7 个「批量 XX」四字按钮加计数需要 774px，而左槽只有 712px 会换行；这一档改用「启用 / 禁用 / 运行 / 停止…」短文案，实测占 695px，余量 17px。

定时任务、环境变量、执行日志三页统一，计数、尺寸、配色、按钮顺序完全对齐。

## 优化：任务名后的标签可以按类别隐藏（#103）

小屏幕上，任务名后面那一排标签很占地方。现在工具栏多了一个「显示设置」下拉，可以**分类**关掉：

| 类别 | 例子 |
|---|---|
| 订阅标签 | 任务所属的订阅名 |
| 分组标签 | `分组:娱乐` 显示出来的「娱乐」 |
| 自定义标签 | 自己打的「京东」「监控」 |
| 类型标签 | 「常规定时」「手动运行」「开机运行」 |

实测把标签全关掉：行高 **74px → 51px**，同屏可见条目 **8 行 → 13 行**。选择会记住，手机端的卡片视图跟随同一开关；任务详情弹窗里的标签**始终完整**，信息不会丢。

> 「已锁定」（订阅锁）刻意不在开关里 —— 它是状态而不是分类标签，藏掉会让人以为订阅同步坏了。

这项需要服务端配合：任务列表接口原来下发的 `display_labels` 是一个扁平数组，订阅名和自定义标签在里面**长得一模一样**，前端分不出来。这一版多下发一份 `subscription_labels`（值取自服务端已经算好的数据，原有逻辑没动）。

## 优化：视图分组栏与状态筛选栏样式统一（#103）

顶部的视图分组栏原来是一排 Element Plus 的实心蓝按钮，和下面的状态筛选栏（灰底槽 + 白底选中）完全是两套观感。而且它**内部本身就不齐**：「全部」按钮比右边的视图按钮矮 8px、字号小 1px。

现在逐项对齐：

| | 状态筛选栏 | 视图分组栏（改后） |
|---|---|---|
| 容器高度 | 39px | 39px |
| 项高 / 内边距 | 33px / `6px 14px` | 同 |
| 字号 / 选中字重 | 13px / 600 | 同 |
| 选中态 | 白底 + 品牌色 + 描边 | 同 |

「新建视图」和「视图管理」两个图标按钮**移到灰底槽外面**——槽里只放筛选项，动作按钮放外面，顺带消掉了高度不一致。

**「全部」也可以隐藏了**：开关在视图管理弹窗里，作为一行带锁图标的内置项（不能拖拽、编辑、删除，只能改显隐）。隐藏后会自动切换到第一个可见视图；如果自定义视图也全隐藏了，会强制把「全部」放回来，不会出现标签栏空掉没法操作的情况。

## 优化：实时日志提到一级按钮（#103）

每行任务的操作区原来只有「运行」是一级，「实时日志」要展开下拉才点得到。现在一级同时有 **运行 / 停止** 和 **日志**，下拉里不再有重复项。

操作列宽度相应从 140px 加到 172px。加宽会从已经压到下限的定时规则列身上扣宽度，所以专门在 1280×720 下量过：cron 表达式 **13 个全部完整显示**，表格无横向溢出。

> 观察者角色的主按钮原本正好就是「实时日志」，日志外置后改成「详情」，两种角色的按钮形态对称、宽度一致。

## 优化：编辑器自动换行 + 脚本目录树可收起（#103）

- **配置文件页与脚本管理页都加了 `Wrap` 开关**，两页共享同一份记忆（一边切换另一边跟着变），刷新后保持。脚本页底部状态栏会显示 `Wrap ON/OFF`。调试弹窗、代码运行器、版本对比保持原样常开，不受影响。
- **脚本管理页可以收起左侧目录树**，编辑区从 714px 扩到 **1028px**。收起后编辑器左上角有展开把手；如果当时没打开任何文件，空状态卡片里也有一个「展开文件树」按钮，不会出现收起后找不到入口的情况。折叠状态会记住。

## 优化：执行日志页的失败角标进页即消（#103）

侧栏「执行日志」的红色数字角标，语义从「今日失败总数」改成了「**未读的新失败**」：

- 进入执行日志页 → 角标（数字和侧栏收起时的红点）立刻消失
- 30 秒轮询回来不会复活，刷新页面也不会复活
- 当天**再有新的失败**，角标重新出现，显示的是新增条数
- 跨零点自动复位；按用户和日期隔离，同一台机器换账号不会串

> 实现上不能直接把计数改成 0 —— 那是 30 秒轮询的服务端数字，最多半分钟就被打回来，表现成「角标自己复活」。这里用的是独立的已读水位 + 计数快照。

同一页的工具栏还修了一处对齐：日期选择器有 630px 宽，把左区挤成了两行，而右边那排按钮只有 32px、被垂直居中在两行的高度里，于是**与左侧状态筛选栏错位 22px**。改成与左区第一行对齐后，错位降到 1px。

## 修复：手动创建的任务被误加「已锁定」标签

用户报的现象是「不是订阅拉取的、我手动创建的定时任务，二次修改定时后也显示已锁定」。

> **根因：加锁逻辑只比对名称和定时有没有变，完全没判断任务属不属于订阅。**

「已锁定」的语义只对订阅拉取来的任务成立 —— 表示用户手改过名称/定时、订阅同步不再覆盖它。手动创建的任务根本没有订阅会来覆盖，这把锁不产生任何行为，只是显示一个误导用户的标签。

「**改两次才出现**」也解释得通：第一次提交时表单里的 cron 和库里的值相同，`改动前 != 改动后` 不成立，所以没触发；第二次真的改了值才加锁。

修复分三处：

| | 改动 |
|---|---|
| 写入点 | 加锁前先判断任务由订阅管理（标签带 `subscription:` 前缀），且用**改动前**的标签判定 |
| 存量数据 | 升级时自动跑一次迁移，把「没有订阅标签却被加了锁」的任务解锁，**不需要手工处理** |
| 任务详情 | 「订阅同步」整行只对订阅任务显示 —— 手动任务原来会看到「跟随订阅源」，同样是错的 |

**升级后那些误标的「已锁定」会自动消失**，面板日志里会留一条 `unlocked N non-subscription tasks` 的记录。

> 过程中堵掉了两个方向相反的坑，都写了会红的测试锁住：
>
> - 迁移若用宽松的子串匹配，自建标签 `my-subscription:foo` 会被当成订阅任务而跳过清理，锁留在库里；而详情页按标签边界判它不是订阅任务、不渲染那一行 → **看得到锁却没有解锁入口，而且永不自愈**。
> - 反过来只卡逗号边界不处理空格，`我的标签, subscription:7` 又会被**误解锁** —— 那是真锁，清掉会让用户手改的定时在下次拉取时被覆盖回去。
>
> 方向是「宁可漏解锁，不可误解锁」：漏解锁只是少清一条脏数据，误解锁会丢用户的改动。

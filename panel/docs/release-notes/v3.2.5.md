## 版本概览

`v3.2.5` 收的是 [#118](https://github.com/linzixuanzz/daidai-panel/issues/118) 里的 4 条建议，**一条不落全做了**。

其中第 1、2 条另一位用户在评论里提了反对意见。这一版没有在「听谁的」之间二选一，而是把两边的诉求拆开看 —— 结果发现它们并不冲突，只是提建议的人和提反对的人各自说的是同一件事的两个侧面。下面逐条说清楚。

---

## 建议 1：运行中的任务自动排到前面

> 在定时任务页面 同级的任务之间 可否支持正在运行的任务自动排到前面

反对意见：

> 第一条的运行中的脚本置顶我建议页面刷新后生效，否则手动点击运行，脚本直接跑最上面去了。另外运行中的脚本本身也可以通过工具栏筛选

**两条都成立，而且反对的那条已经被代码坐实**：任务列表有一个 **3 秒**一轮的状态轮询，而且它是**整表替换** —— 服务端给什么顺序就画什么顺序；点「运行」之后前端还会**当场**再拉一次列表。所以一旦服务端把运行中排到前面，一次运行会**跳两次**：起跳一次、跑完再跳回来一次。cron 密集的面板每分钟都有任务起落，列表会持续抖动。

### 改成了什么

把「顺序」和「状态」拆开：

- **服务端**在默认排序里加了一层「运行中优先」：
  `置顶 → 状态分组 → **运行中优先** → 拖拽顺序 → 开机执行顺序 → 创建时间`。
  因为是服务端排的，所以**跨页有效** —— 第 3 页正在跑的任务真的会出现在第 1 页，这是纯前端重排做不到的。
- **前端**的状态轮询和「点运行后的回读」改成**按 id 就地刷新字段、不动数组顺序**。
  于是：点「运行」那一下**不跳**，轮询期间也**纹丝不动**；顺序只在你**主动刷新 / 切筛选 / 搜索 / 翻页 / 增删改任务**时才按新规则重排 —— 这正是评论里说的「页面刷新后生效」。

一句话：**提建议的人要的「不用切筛选就能看到」拿到了，提反对的人要的「点了别乱跳」也拿到了。**

### 三条边界

1. **只提「运行中」，不提「排队中」。** 排队是瞬时态，提了只会多一次跳动。
2. **只在默认排序里生效。** 你显式点了「名称 A→Z」或用视图排了序，运行中**不会**越过你的规则 —— 只有规则全部打平时才轮得到它。（这和 v3.2.4 加的「置顶与状态分组压在所有规则之上」不是同一层，别混。）
3. **跑完自动回原位**，不会改写你的拖拽顺序。

### 一个已知代价，先说清楚

任务多到分页时，**在第 2 页及以后点「运行」，那一行会离开当前页**（它被提到第 1 页了）。这是「服务端全局置顶 + 分页」的结构性后果，不是前端能消掉的。

### 还有一条：拖拽排序在有任务跑时会被暂时禁用

运行中的位置是**临时**的，而拖拽的落点是按**稳定顺序**算的 —— 把一行拖到一个临时占位的行上方，这件事在语义上就是未定义的（实测下来会出现「拖了个寂寞」甚至「拖到第一行反而跑到最后一行」）。所以列表里有任务在跑时，拖拽手柄会被禁用并告诉你原因和什么时候能拖。与其猜你想干什么，不如说清楚现在不能拖。

> 顺带确认一下评论里那句：**工具栏的「运行中」状态页签确实已经存在**，视图的高级筛选里也有。这一版没有动它。

## 建议 2：环境变量按变量名筛选

> 环境变量页面 可否支持按照变量名来筛选 有很多同名变量 一个个分组有点麻烦

反对意见：

> 第二条不是有搜索功能吗

**这句只对了一半。** 搜索框确实能搜到变量名，但它是 `name` / `value` / `remarks` / `group` **四个字段的模糊 OR**，没法限定字段。实测：库里放 7 条变量，搜 `JD_COOKIE` 会命中 **6 条** —— 包括值里含这串的、备注里写了的、以及名字是 `JD_COOKIE_EXTRA` 的。

而更关键的是另一半：**面板对「变量名」这个天然聚合键几乎零能力**。没有按名筛选、名称不可点、没有「共 N 条」计数；列表默认序是手工拖拽序、每页 20 条，所以**同名的几条会散落在不同页**。提建议的人说「一个个分组有点麻烦」，正是在用**手工分组**去模拟一个**本该自动**的按名聚合 —— 名字本来就是聚合键，不该还要用户再打一遍标签。

顺便说明：**同名多条是面板刻意支持的功能**，不是脏数据。多账号场景下运行时会按 name 分组、用 `&` 拼起来给脚本；面板里「复制同名变量」和新建时的「每行创建一个变量」这两个入口就是用来量产同名变量的。所以「有很多同名变量」是被引导出来的正常状态。

### 改成了什么

把「变量名」做成和「分组」**同构**的一等筛选维度：

- 新增 `GET /api/envs/names`，返回 `[{name, count}]`；
- 列表接口新增 `names` 参数，**精确**匹配（`JD_COOKIE` 不会带出 `JD_COOKIE_EXTRA`），多值 OR，与关键字 / 分组 / 状态之间是 AND；
- 工具栏多了一个**变量名筛选**下拉（带搜索，名字上百个也能用），选项直接显示 `JD_COOKIE (3)` —— 哪些名字有多条，一眼就看见；
- **名称单元格可以点** = 一键「只看这个变量名的全部条目」。

实测同一份数据：`keyword=JD_COOKIE` 模糊命中 6 条，`names=JD_COOKIE` 精确命中 3 条。

> `count` 是**全库**同名条数，不跟随当前筛选 —— 它和「按名更新变量时冲突报的那句『存在 N 条名为 X 的环境变量』」是同一个 N，两处不会给出不同数字。

## 建议 3：上传同名脚本不再重复问

> 上传同名更新的脚本 仍然会提示是否添加到定时任务 可否支持已有任务就不重复弹出了

这个弹窗此前的判定条件**只有一条**：本次上传恰好成功落盘 1 个文件。完全不看有没有任务引用它。

### 改成了什么

上传后先看两件事：

1. **扩展名**能不能被执行（`.py` / `.js` / `.mjs` / `.ts` / `.sh` / `.go`）。顺带修掉一个一直存在的噪音：面板允许上传 `.json` / `.md` / `.png`，所以以前**上传一个 `config.json` 也会问「是否添加到定时任务」**，点确认还会生成一条永远跑不起来的 `task config.json`。现在这类文件一条提示都不会有。
2. **有没有任务已经引用了这个脚本**。有 → 不再弹确认框，改成一条不阻断的提示：`该脚本已有 N 条定时任务，未重复询问`；没有 → 照旧弹。

### 匹配是怎么做的

**不是**逐字比对命令，也**不是**拿文件名做包含判断 —— 那两种都会错。同一个脚本在库里至少有 8 种合法写法（`task x.py now`、`task -m 30m x.py`、`desi x.py VAR 2`、`python3 x.py`、`task "a b/x.py"` …），逐字比对基本等于没修；而拿文件名裸包含会把**子目录里的同名脚本**误判成同一个（`task jd/qd.py` 会被当成引用了根目录的 `qd.py`），从而**错误地吞掉弹窗**。

所以是按面板执行器自己的规则**解析出脚本路径再整体相等比较**，大小写敏感。已禁用的任务也算进「已有」，提示里会写明。

拉不到任务列表（离线 / 报错）时**一律回落成照旧弹窗** —— 宁可多问一次，也不能因为一次网络抖动就把「上传后一键建任务」这个入口静默吞掉。

> 编辑器右上角的「添加任务」按钮**保持不拦**：同一脚本按账号拆 `desi` / `conc` 建多条任务是文档推荐的正常用法，那是你的逃生门。

## 建议 4：更新日志终于渲染 markdown

> 更新日志里面都是markdown语法 但是并不支持markdown的渲染 看着很难受

截图里那个「发现新版本」弹窗，此前正文就一行 `<pre>{{ 更新日志 }}</pre>` —— markdown 原文一字不差地摊在那儿，星号、`>`、`---`、`[文字](链接)` 全是生的，连每份日志第 2 行那条 HTML 注释都照抄出来。

### 改成了什么

写了一个**极简 markdown 渲染器**，支持这份日志实际会用到的全部语法：标题、加粗、斜体、行内代码、围栏代码块、有序/无序列表（含嵌套）、引用、分隔线、链接、**GFM 表格**。正文字体也从等宽换回了正常 UI 字体，只有代码保留等宽。

**为什么自己写而不是引一个 markdown 库**：这个仓库的前端有一条分包规则会把 `node_modules` 里的东西扫进**首屏预加载**的 chunk，而且**写 `await import()` 也躲不掉**（它决定的是模块归属，不是加载时机）。引库要么额外改分包规则并补一条 CI 断言，要么就是给每一个打开面板的人静默增加约 62KB 首屏。自研的渲染器跟着设置页的懒加载走，**首屏成本是 0**。选型的依据是把 71 份历史更新日志全扫了一遍：语法面很窄且很稳（没有图片、删除线、脚注、表格对齐），唯一必须支持的重头是表格 —— 最近 10 个版本每一份都有。

### 安全上做了什么

更新日志的内容来自 GitHub，属于**外部输入**，直接塞进页面就是 XSS。所以：

- **先转义再拼装**，绝不是「先拼 HTML 再过滤」；
- **行内代码内部也转义** —— 日志里有 20 多处 `` `<style>` `` `` `<meta>` `` 这类，漏了就是真标签注入；
- **链接只放行 `http` / `https`**，其余（含 `javascript:`、`data:`、相对路径）一律降级成纯文本；放行的加 `noopener noreferrer`。

实测：构造了一份带 `<script>` / `<img onerror>` / `<style>` / `javascript:` 链接 / 大小写混写协议 / `data:` 链接的恶意日志，**4 次注入尝试全部失效**，页面里零危险标签、零事件属性，行内代码里的 `<script>` 正确显示成文字。

渲染整段包了兜底：万一抛异常，回落到原来的纯文本显示 —— 这个弹窗是有新版本时**自动弹**的，不能让它把设置页开出一块白。

### 顺带修掉一个一直坏着的东西

更新日志里写过 `[定时任务不执行 / 没有日志](../task-not-running.md)` 这类**相对链接**。实测确认：GitHub 的 Release 页面会把它渲染成 `href="/linzixuanzz/daidai-panel/blob/task-not-running.md"` —— **没有 ref、没有目录，是一个 404**。原因是 Release 正文没有「源文件路径」这个上下文。

所以从这一版起，更新日志里一律写绝对链接，并在发版门禁里加了一条断言把它钉死。

## 接口变化（都只增不改）

| 变化 | 说明 |
|---|---|
| 新增 `GET /api/envs/names` | 返回 `[{name, count}]`，按名升序；`count` 是全库同名条数 |
| `GET /api/envs` 新增 `names` 参数 | 精确匹配变量名，多值 OR，与其它筛选 AND |
| `GET /api/tasks` 默认排序 | 多了「运行中优先」这一层（**只在默认排序生效**，显式排序不受影响） |

API 文档已同步，并顺手补齐了 `GET /api/envs` 上**一直漏记**的 `groups` / `group` / `enabled` 三个参数。

## 验证到什么程度

- 后端 `go test ./... -count=1`：11 个包全绿。新增/改写的用例钉住了：运行中排到本区最前、跑完回原位、**显式排序时运行中不越位**、置顶区不受影响；以及 `names` 的精确匹配（`JD_COOKIE` 不带出 `JD_COOKIE_EXTRA`）、多值、与其它筛选的 AND、传不存在的名字返回空而不是全量。
- 前端 `npm run build`（含 `vue-tsc`）通过；首屏 `vendor` chunk **一字节没涨**。
- **起了一套真实实例，用 Chrome 逐项实测**：
  - 运行中优先：轮询期间把某条任务改成运行中 → **状态刷新了、位置纹丝不动**；刷新页面 → 它被提到本区最前；改回空闲并刷新 → 回到原位。两位用户的诉求同时成立，这是量出来的。
  - 变量名筛选：下拉显示 `JD_COOKIE (3)`，选中后只剩 3 行；点名称单元格等价于选中它；对照 `keyword` 模糊搜索命中 6 条。
  - 上传：已有任务的脚本 → 只出一条提示、不弹确认框；没有任务的 → 照旧弹；`config.json` → 一条都不弹。
  - 更新日志：拿本仓真实的 v3.2.4 日志渲染，1 个 h1 / 12 个 h2 / 7 个 h3 / 74 处加粗 / 50 处行内代码 / **2 张表格** / 14 处引用全部正确，**可见文本里零原始 markdown 标记**；再拿恶意日志验了转义与链接白名单。
- 改动落地后又做了一轮**多维度对抗性代码审查**，确认并修掉了 8 条，其中两条是本轮自己引入的回归（列表就地合并在「运行中」筛选下会让跑完的任务永远卡住、以及拖拽落点的问题），一条是列表项软换行被渲染成独立段落（71 份日志里共 52 处）。

## 本版没做的

- **没有**改动任务列表的其它排序层级，也**没有**把「运行中优先」并进拖拽分桶（那会让桶随任务起落漂移）。
- **没有**给环境变量做「按名称折叠父子行」（与拖拽排序、置顶区、分页三处冲突），也没有加按名称的快捷排序。
- **没有**改动上传的后端行为（同名文件仍是覆盖，且不记版本 —— 那是另一件事）。
- **没有**引入任何新的前端依赖。
- **没有**改动 Magisk 模块外壳脚本、Docker entrypoint、Dockerfile 与 `docker/nginx.conf`。

## 关于 APP

本版**没有** APP 侧改动，APP 不需要跟随升级。

接口面只有增量：新增的 `GET /api/envs/names` 与 `GET /api/envs` 的 `names` 参数，不调就完全不受影响。唯一会被感知到的是 `GET /api/tasks` 在**不传排序规则**时的顺序里多了「运行中优先」一层 —— 响应结构没变。如果 APP 的任务列表也是「拉一次画一次」，那它会直接得到这个效果；若它也有轮询，建议同样改成「按 id 就地刷字段、不动顺序」，否则会复现本文开头说的那个抖动。

## 升级方式

| 部署方式 | 操作 |
|---|---|
| Docker | 重新拉取镜像后重建容器（本版没有改动 entrypoint 与 Dockerfile） |
| Magisk 模块 | 面板内一键更新即可（本版**没有改动模块外壳脚本，不需要重刷 ZIP**） |
| 裸机 / Windows | 面板内一键更新，或下载新版二进制替换 |

本版**没有任何数据库变更**，升级即用。

**升级后值得看一眼的地方**：环境变量页工具栏多了一个「变量名筛选」下拉；有同名变量的话，选项后面的 `(N)` 会直接告诉你哪几个名字有多条。

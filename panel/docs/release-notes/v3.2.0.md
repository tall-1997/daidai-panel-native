## 升级须知

### 1. 青龙订阅的 `$QL_DIR` 取值变了（修 bug 的行为变更）

`v3.0.6` 起，订阅的「拉取前指令 / 拉取后钩子」里可以用 `$QL_DIR`。**但它一直是错的**：
容器里算出来是 `/app/Dumb-Panel`，于是照青龙写法拼出来的 `$QL_DIR/data/repo` 指向一个**根本不存在的目录**。

本版把它修正成 `/ql`（兼容层建不出来时回落数据目录），并让**任务执行**也能拿到这个变量。
如果你之前照着发布说明在钩子里用过 `$QL_DIR`，那段脚本当时就是坏的；升级后它会指向真实存在的路径。

### 2. 代码编辑器从 Monaco 换成了 CodeMirror 6

脚本管理、配置文件、代码运行器、调试弹窗、版本对比这 5 处编辑器全部换了引擎。
语法高亮、自动换行、只读态、自定义编辑器底色、明暗主题、搜索、折叠、括号自动闭合、自动补全都在。

**去掉的有三样**，都写清楚：

| 去掉的 | 原因 |
|---|---|
| minimap（右侧代码缩略图） | CodeMirror 6 没有内建 minimap，为一个缩略图引一份非官方第三方包不划算；长文件导航由代码折叠 + `Ctrl+F` 搜索面板承担 |
| **多光标 / 列选**（Alt+点击、Alt+Shift+拖拽） | 次光标与次选区要靠编辑器自绘选区层才能画出来，而**那一层正是必须关掉的东西** —— 关掉它才有原生 `Selection`，手机上才会出现系统的选择手柄。这是同一枚硬币的两面，不是漏做 |
| **编辑器自带的右键菜单** | 换成浏览器/系统的原生右键菜单。桌面上少了「命令面板 / 格式化文档」等入口；而这恰恰就是移动端那条诉求本身 |

顺带的收益：`dist/monaco` 那套约 5MB 的运行期资源整个消失，前端产物明显变小，
离线部署也不再需要「本地资源探测 + CDN 兜底」那一整套机制。

## 新增：青龙脚本兼容层与订阅「完整检出」（#110）

用户订阅了 `RayWangQvQ/BiliBiliToolPro`，白名单填 `bili_task_`，面板正常检出了
`qinglong/DefaultTasks/bili_task_*.sh` 并建成任务，但每个任务跑起来都是这样：

```
touch: cannot touch '/ql/shell/env.sh': No such file or directory
bilitool: 青龙repo目录: /ql/data/repo
find: '/ql/data/repo': No such file or directory
=== 执行结束 耗时 0.09 秒 退出码 1 ===
```

### 根因是两个缺口叠加

我们把上游的 `bili_task_base.sh` 原文拉下来对了一遍，它开头做两件事：

```bash
QL_DIR=${QL_DIR:-"/ql"}
dir_shell=$QL_DIR/shell
dir_repo=${dir_repo:-"$QL_DIR/data/repo"}

touch "$dir_shell/env.sh"                                          # ← 报错 1
repo_dir=$(find "$dir_repo" -type d -name "owner_repo" | head -1)  # ← 报错 2
```

1. **面板运行期完全没有青龙目录兼容层**：容器里没有 `/ql`，任务环境里也没有 `QL_DIR`，
   于是 `${QL_DIR:-"/ql"}` 取默认值，第一行就 `ENOENT`，`set -e` 直接把脚本带出去。
2. **sparse 检出只落了白名单命中的 `.sh`**：即便路径对了，脚本 `find` 到仓库目录后还要读
   `src/` 下的源码去编译，而那些文件一个字节都没落盘。

### 这一版的改法

| 做了什么 | 落在哪 |
|---|---|
| 启动时把青龙布局映射到面板真实目录（`/ql/data/repo` → 脚本目录、`/ql/data/log` → 日志目录、`/ql/data/config` → 数据目录、`/ql/shell/env.sh` 空占位……） | `server/service/qinglong_compat.go`（新增），`server/main.go` 启动期调用 |
| 容器 entrypoint 里以 root 再做一遍，并把 `/ql` 一起 `chown` 给降权用户 | `docker/entrypoint.sh` |
| 任务执行环境注入 `QL_DIR` / `QL_BRANCH` / `QL_REPO_PATH` / `QL_SCRIPT_PATH` / `QL_LOG_PATH` / `QL_CONFIG_PATH`，以及青龙的 `dir_repo` / `dir_scripts` / `dir_raw` | `server/service/runtime_exec.go` |
| 订阅新增「完整检出」开关（默认关，存量订阅行为零变化） | `server/model/subscription.go`、`server/database/database.go`、`server/handler/subscription.go`、`server/service/subscription.go`、订阅表单 |
| 修正 `$QL_DIR` 在订阅钩子里的错误取值 | `server/service/subscription_hook.go` |
| 文档 | `docs/script-api.md` 新增「青龙脚本兼容层」一节 |

**这套映射能对上，靠的是一个巧合**：面板订阅的检出目录名（`save_dir` 默认取 `<owner>_<repo>`）
与青龙 `/ql/data/repo/<owner>_<repo>` 的目录名**逐字相同**，所以一条软链就能把两边接上。

### 为什么光有软链还不够 —— 一个只有实跑才会暴露的坑

软链能兜住 `cd` / `ls` / `test -d` / `source` / 重定向，**唯独兜不住 `find`**。

GNU `find` 默认是 `-P`，**命令行参数本身是软链时不会下钻**。实测：

```
find <软链>      -> 空          ← 青龙脚本正是这么写的
find <软链>/     -> 命中        ← 但我们控制不了脚本怎么写
find <真实目录>  -> 命中
```

所以除了软链，还必须把青龙的 `dir_repo` / `dir_scripts` / `dir_raw` 直接注入成**真实路径**。
青龙脚本写的是 `dir_repo=${dir_repo:-...}`，会优先采用我们给的值，`find` 也就正常了。

> 这批 `QL_*` / `dir_*` 与 `DAIDAI_*` / `TZ` 那些保留名**语义相反**：
> 它们**只在你没有定义同名变量时才注入**，你在「环境变量」页面自己建的会赢。

### 边界（写清楚，别当成「装好就一定能跑」）

- `/ql/data/repo` 指向整个脚本根目录，青龙脚本 `find $dir_repo` 会看到**面板里所有订阅仓库**。
  对「按 `<owner>_<repo>` 精确定位自己」的脚本无害，对「遍历 repo 目录批量做事」的脚本可能误伤。
- 兼容层只补齐**目录与环境变量**。脚本自身的运行时依赖不在面板职责内 ——
  BiliBiliToolPro 需要 dotnet 才能编译运行，那一步得你自己在容器里备好。
- 只读根 / 异常挂载 / 权限不足时兼容层会建不出来。这时**只在面板日志里留一行提示，不影响面板启动**。
- Windows 单机版没有 `/ql` 的对位概念，静默跳过。

### 验证到什么程度

- **已在真实 Linux（WSL Ubuntu 24.04）实跑**：`docker/test-entrypoint-puid.sh` 补了青龙断言并全部通过 ——
  3 条关键软链（`/ql/data/repo`、`/ql/data/config`、`/ql/data/log`）指向正确，
  且 `/ql/shell/env.sh` 的属主确实是降权用户（青龙脚本第一步 `touch` 它才不会失败）。
- **已按原样复现 issue 里那两条报错并验证消失**：先在没有兼容层的环境里复现
  `touch: cannot touch '/ql/shell/env.sh'`，建好兼容层后 `touch` 通过；再验证只有软链时
  `find "$dir_repo"` 仍然找不到，注入 `dir_*` 之后才真正定位到仓库目录。
- **8 条软链映射的完整断言**在 `server/service/qinglong_compat_test.go`（Go 单测，跑在临时目录的假根上），
  这批用例也交叉编译成 Linux 二进制在 WSL 里实跑通过（Windows 上它们会 skip）；
  `server/service/docker_entrypoint_assets_test.go` 另做 8 条的静态一致性断言。

**未验证**：真实 Docker 容器与 Magisk 设备上的端到端；BiliBiliToolPro 全流程（需要 dotnet 环境）。

## 优化：定时任务点「日志」不再固定等 1.5 秒（#109-1）

用户在 Android magisk-debian 上实测，点日志按钮到出内容约 2 秒。

### 根因

`server/handler/log.go` 里有一句**无条件**的 `time.Sleep(1500 * time.Millisecond)`。

它本意是兜「刚点运行、执行器还没建好实时日志缓冲」的启动竞态，但生效条件写成了
「任务状态 != 运行中」，于是把**已禁用**和**已启用（未在跑）**这两个根本不可能有竞态的状态一起罚了 ——
而「点日志看上次跑完的结果」恰好 100% 落在这两个状态上。

更糟的是这 1.5 秒里服务端**一个字节都没写**，HTTP 响应头也压着没发，
前端的连接一直挂起、连「加载中」的骨架都出不来，所以是纯白屏转圈，感知上被放大。

### 这一版的改法

| 改了什么 | 效果 |
|---|---|
| 固定 sleep 换成**短轮询**：每 150ms 探一次、封顶 1.5s，一出现就立刻进流式分支 | 手动运行这条主路径覆盖不变，正常场景 0 等待。**定时触发存在一个极短的未覆盖窗口**（调度器是先入队、再置排队中，两句之间那一瞬），恰好在那一刻打开弹窗会直接显示「已完成」，重开一次即恢复 —— 刻意用它换掉所有人每次都罚的 1.5 秒 |
| 进 handler 立刻 flush 一次响应头（一条 SSE 注释行） | 弹窗骨架先出来，不再白屏 |
| 前端把 `latest-log` 的请求与日志流**并行发起**，而不是等流结束才发第二个往返 | 弱机上省掉一整个往返（鉴权 + 查库 + 全量解压） |

### 一个自己给自己埋的坑，也一并说明

并行预取有个陷阱：预取拿到的是「打开弹窗那一刻」的快照。
任务在一两秒内跑完时，预取仍在有效期内 —— 复用它就会**用旧快照覆盖掉刚跑完的正确日志**
（很可能整份是**上一次运行**的输出，或者一条内容还是空的新记录，被显示成「日志已过期」）。
光靠一个时间阈值挡不住：任务跑得越快，两者越接近。

所以判据交给服务端来给：`done` 事件现在有三种载荷 ——
`reconnect`（任务在跑，前端重连续流）、`finished`（服务端一秒没等、任务早就结束）、
`finished-late`（服务端在短轮询里真的等过，说明打开弹窗时任务还在启动或运行）。
**只有 `finished` 才允许复用预取**；另外两种、以及流里一收到真实数据，预取立刻作废并 abort
在途请求（运行中的大日志任务那一份可能有几十 MB，不掐断等于在弱机上白下一遍）。

> 对独立仓库里的 APP 与演示站是向后兼容的：未知载荷按 `finished` 处理，最坏退回旧行为。

### 明确没做的

- `latest-log` 没有加尾部截断：会影响复制/下载（它们依赖完整内容），且该接口对 Open API 暴露，属对外行为变更。
- 没给日志表加复合索引：老库上 AutoMigrate 撞已有同名索引会让面板直接起不来，这个风险只能在真实老库上验，跑单测验不出来。

## 优化：编辑器换成 CodeMirror 6，手机上能用系统自己的编辑方式了（#109-2）

用户在手机上用网页端编辑脚本时：长按弹出的是编辑器自己的菜单栏而不是系统菜单；
双击能选中连续文本但不出现可拖动的选择手柄；按住光标拖不动。

### 根因不是「少配了某个选项」

Monaco 是**自绘编辑器**：文本渲染在它自己的 DOM 层里、浏览器原生选择被关掉，
选区和光标都是它画出来的，真正的键盘输入走一个视觉上隐藏的辅助元素；
触摸事件被它内部的手势层接管，长按被识别成「右键菜单」手势。

所以用户那三个诉求**只要还用 Monaco 渲染就都不可能满足**：
选择手柄和拖动光标是操作系统在**原生 Selection 存在时**才绘制的，
而 Monaco 的选中是它自己画的高亮块，`document.getSelection()` 里压根没有对应的选区。
把 `contextmenu` 关掉只会让长按之后「什么都不出现」。

CodeMirror 6 的内容区是 `contenteditable`，选区就是原生 `Selection` —— 三条全部天然可用，且保留语法高亮。

### 这一版的改法

5 个使用点（脚本管理 / 配置文件 / 代码运行器 / 调试弹窗 / 版本对比）整体换掉，
连带删除整套「运行期 AMD 加载 + 本地资源探测 + CDN 兜底 + 构建后拷贝 5MB 资源」的机制。

保住的既有行为：保存与脏检查、只读态、自动换行偏好（两页共享）、自定义编辑器底色、
明暗主题、11 种语言的语法高亮（js / ts / python / shell / go / json / yaml / markdown / html / css / xml；
其余扩展名按纯文本处理）、搜索、折叠、括号自动闭合、自动补全。

移动端另外补了三件必须的事：关掉输入法的自动大写 / 自动纠错 / 拼写检查
（否则手机输入法会**静默改坏脚本内容**），以及把 ≤768px 的内容区字号提到 16px
规避 iOS 聚焦时自动放大整页。

### 一处需要说明的行为差异

版本对比弹窗的「忽略空白差异」开关，Monaco 的语义是对每行**首尾都 trim**。
换引擎时如果只抹行尾，「一处真实改动 + 一段重新缩进」的混合版本对就会把那段缩进重新标成差异。
本版按 Monaco 的原语义实现（首尾都抹），与开关文案「只检测到空格、缩进或换行变化」一致。

### 验证到什么程度

仓库**没有前端自动化测试**（`web/package.json` 无 test 脚本、无 vitest），
所以这一节的保护只有 `npm run build`（含 `vue-tsc -b`）加人工回归。本轮实测到的：

- **桌面浏览器（Chrome 152，本地起了一套完整实例）逐项量过**：
  组件根类名与页面 `:deep()` 选择器对得上（这类不匹配是构建和类型检查都发现不了的静默失效）；
  只读态 `contenteditable=false`、点「编辑」后变 `true`；输入一个字符后「未保存」角标**立刻**出现（不是等失焦）；
  Wrap 开关 ON→OFF 后 `white-space` 真的从换行变成 `pre`；行号 + 折叠槽都在，点折叠会出现 `…` 占位符、可见行数随之减少；
  `Ctrl+F` 搜索面板能打开；切换暗色后 `--dd-editor-bg-color` 从 `#ffffff` 变成 `#111827`、编辑器底色/文字/行号槽全部跟着变。
- **换引擎的核心目的也量到了**：选中一段文字后 `document.getSelection()` 真的返回那段文本。
  Monaco 下这里是空的 —— 这正是系统画不出选择手柄的原因。
- **未在真机上实测**：「长按出系统菜单 / 双击出选择手柄 / 按住拖动光标」这三条最终诉求
  依赖具体系统与浏览器的实现，本轮**没有在 Android / iOS 真机上验过**。
  技术前提（原生 `Selection` 存在、`contenteditable` 内容区、输入法自动大写/纠错已关闭）都已确认成立。

## 修复：订阅标签与分组标签重名时，两个显示开关互相串台（#109-3）

用户报的现象很精确：订阅名和分组名一样时，取消勾选「订阅标签」标签不消失；
取消勾选「分组标签」两个标签一起消失。

### 根因：类别寄生在字符串值上

前端判定一条标签属于哪一类，靠的是**拿它的文字去比对**：

```ts
if (groupName && label === groupName) { group.push(label); continue }  // ← 先判分组，且 continue
if (subscriptionSet.has(label))       { subscription.push(label); continue }
```

只要订阅名等于分组名，两条标签都会在第一行命中并 `continue`，**订阅那一桶永远是空的**。
后面按 `Set` 做显隐过滤时同样是按字符串成员判定，所以只改分类那一处不够，两处必须一起改。

顺带说明：服务端下发的 `display_labels` 里确实有两条同名项 —— **这是正确数据**，
需求要的「取消分组后订阅标签还在」只有在保留两条的前提下才谈得上。

### 这一版的改法

- 分类改成按**下标一一对齐 + 名额消费**：分组名认领第一条匹配项，订阅名按下发的订阅标签出现次数认领，
  向下游传「复合 key + 类别」，不再让字符串值决定类别。
- 显隐过滤改按类别查，删掉两个 `Set`。
- 两处模板换成复合 key，顺带解决了 Vue 的重复 key 警告。
- **给标签按类别加了可分辨的配色** —— 不然修好之后并排两个一模一样的名字，用户仍然不知道该关哪个开关。
- **姊妹 bug 一并修**：服务端组装标签时「分组 / 订阅 / 自定义」三类**共用一个去重集合**，
  于是「自定义标签名 = 订阅名」时两条会被合并成一条，表现为「取消自定义藏不掉它、取消订阅反而把它藏了」。
  按类别把去重集合拆开，并补了回归测试锁住「同名两条都在」这个契约。演示站的假后端同步改。

## 优化：环境变量页状态与开关分离，操作栏对齐定时任务页（#109-4）

按用户给的图和描述做：

| 需求 | 做法 |
|---|---|
| 状态用红/绿小圆点显示在**名称前** | 名称列前加 8×8 圆点（启用绿 / 禁用红），带 `title` 与无障碍标签 —— 红绿是最典型的色觉障碍撞色对，不能只靠颜色传达 |
| 开关移到操作栏「编辑」右侧 | 启用态显示「禁用」（白底红字红描边），禁用态显示「启用」（白底），与工具栏「批量启用 / 批量禁用」同一套组合 |
| 整体与定时任务页操作栏一致 | 去掉本页那条为了挤进 110px 列宽而加的内边距收窄覆写，改回与定时任务页相同的默认值；列宽按同一套口诀重算成 **172**，与定时任务页恰好相同 |
| 操作栏常驻、对小窗口更友好 | 操作栏本来就是常驻的（这一条是要守住的不变量）；真正 hover 才出现的是**值列的复制按钮**，本版改成常驻；操作列同时加了右侧固定 |

原来那一列 92px 宽、只为显示一个布尔值的「状态」列整个删掉；移动端卡片同步改成同一套圆点 + 按钮，
不再是「桌面一套、手机另一套」。

## 升级方式

| 部署方式 | 操作 |
|---|---|
| Docker | 重新拉取镜像后重建容器（青龙兼容层的 entrypoint 部分**需要新镜像**才会生效） |
| Magisk 模块 | 面板内一键更新即可（本版**没有改动模块外壳脚本，不需要重刷 ZIP**） |
| 裸机 / Windows | 面板内一键更新，或下载新版二进制替换（Windows 单机版没有青龙兼容层，其余改动照常生效） |

# v3.2.2
<!-- release-title: 编辑器补齐缩略图 / 缩进参考线 / 空白符 / 差异标尺 / 光标横向跟随五项，并把 Monaco 作为可切换的第二引擎带回桌面端；环境变量禁用行整行弱化 -->

## 版本概览

`v3.2.2` 是一个**编辑器专版**，把 v3.2.0 换引擎时丢掉的便利性一次补齐。本版共处理 **issue #114 的 6 项诉求 + #109 关闭后追加、此前一直没被回应的 2 条建议**：

- [#114](https://github.com/linzixuanzz/daidai-panel/issues/114)（6 条）：CodeMirror 6 缺少 minimap（代码缩略图）、缩进参考线、空白符显示、Diff 视图滚动条上的增删行标记、点击光标后的横向跟随；以及「能否双编辑器自动判断设备分配，或手动切换」。
- [#109](https://github.com/linzixuanzz/daidai-panel/issues/109) 追评（2 条）：版本差异对比窗口右侧拖动条上的差异位置标记也没了；环境变量页禁用掉的变量，希望整行视觉上弱化一点。

**五项编辑器功能在两个引擎上都可用，切换入口在编辑器工具栏的齿轮菜单里。**

本版有**两处必须先看的变更**（引擎默认值在桌面端变了、切换引擎会丢撤销历史），见升级须知。
本版**没有**改动 Magisk 模块外壳脚本，**不需要重刷 ZIP**；也没有改动 Docker entrypoint 与 Dockerfile，但**改了 `docker/nginx.conf`**（见下文）。

感谢 [@hlt1995](https://github.com/hlt1995) 提的 #114 与 #109 追评 —— 两次反馈都做了同一件很难得的事：**把「少了什么」逐条编号列清楚，而不是笼统说「不好用」**。#114 里那句「相比之下 Monaco 编辑器在桌面端使用更加便利，为了移动端的编辑方式失去了桌面端的一部分体验有点得不偿失」，是本版决定把 Monaco 作为可选引擎带回来的直接原因 —— 它准确指出了 v3.2.0 那次取舍的真实代价：**移动端赢了，桌面端输了**，而这两件事本来不必二选一。

## 升级须知

### 1. 桌面端默认会用上 Monaco 引擎

编辑器现在有三档引擎设置，默认是**自动**：

| 设备 | 自动档落到 |
|---|---|
| 触摸设备（`pointer: coarse`），无论屏幕多宽 | **CodeMirror 6** |
| 视口宽度 ≤ 1024px | **CodeMirror 6** |
| 其余（桌面端） | **Monaco** |

也就是说：**升级后你在电脑上打开脚本，看到的是 Monaco；在手机 / 平板上打开，仍然是 CodeMirror。** 不接受这个默认值的话，齿轮菜单里可以手动锁定成 `CodeMirror` 或 `Monaco`，选择记在浏览器本地（`dd:editor:engine`），与「自动换行」那套是同一类偏好。

**为什么触摸设备一律不给 Monaco，而且不打算做成可选：** Monaco 是自绘编辑器，文本画在它自己的层里、原生选区被关掉（非 Safari 的浏览器上它还会给内容区加 `user-select: none`），触摸事件被内部手势层接管 —— 于是「长按出系统菜单 / 双击出选择手柄 / 按住拖动光标」这三条**只要还用它渲染就都不可能满足**。这正是 v3.2.0 换掉它的全部理由（见 [#109](https://github.com/linzixuanzz/daidai-panel/issues/109)）。自动档按 `pointer: coarse` 判定而不是只看宽度，就是为了不漏掉 1024~1366 的平板横屏和触屏笔记本 —— 它们宽得像桌面，但把 Monaco 发过去等于把那三条能力又收回去。

> 你仍然可以在手机上手动选 `Monaco`。菜单不拦你，但上面那三条会一起消失，这是引擎本身的性质，不是配置问题。

### 2. 切换引擎会丢掉撤销历史

换引擎意味着整块重建编辑器实例。**正文内容不会丢**（它活在页面状态里），但**撤销 / 重做栈、光标位置、滚动位置会全部重置**。有未保存改动时切引擎，改动本身还在，但按 Ctrl+Z 已经撤不回去了。

### 3. Docker 部署请一并更新 `docker/nginx.conf`

Monaco 的图标字体是本仓库第一个 `.ttf` 产物（`codicon-*.ttf`，约 138 KiB），而原来的静态资源缓存规则里**没有 `ttf`**。漏改不会 404、控制台也不会报错，只会**静默丢掉 `expires 30d` + `immutable`** —— 每次进页面都回源重新校验一次。本版已把 `ttf` 加进缓存规则与 `gzip_types`（压后约 67 KiB）。

自建 nginx 的用户请同步这一行。**Magisk / Debian / Windows 内嵌部署不受影响**（走 Go 静态托管，没有这条规则）。

## issue #114：五项编辑器功能

先说结论，两个引擎的落地方式不同但效果一致：

| # | 诉求 | CodeMirror 6 | Monaco |
|---|---|---|---|
| 1 | 代码缩略图（minimap） | 自建（本版新增） | 原生 |
| 2 | 缩进参考线 | 自建（本版新增） | 原生 `guides.indentation` |
| 3 | 空白符显示（灰点 / Tab 箭头） | 内置 `highlightWhitespace` | 原生 `renderWhitespace` |
| 4 | Diff 滚动条上的增删行标记 | 自建总览标尺（本版新增） | 原生 overview ruler |
| 5 | 点击光标后横向跟随 | 自建（本版新增） | 原生，一直就有 |

前三项是**开关**，在编辑器工具栏的齿轮菜单「编辑器选项」里，脚本管理页与配置文件页共享同一份记忆。默认值：

- **缩进参考线：默认开**。它就是为了让缩进层级一眼看清，噪声极低。
- **代码缩略图：默认关**。它要占掉正文右侧的宽度，窄屏尤其肉疼。
- **空白符：默认关**。每个空格一个灰点，平时读配置文件时纯属干扰。

第 4、5 两项没有开关，一直生效。

### 1. 代码缩略图

CodeMirror 侧是自己写的（`web/src/utils/codeMinimap.ts`），**没有引第三方包**。社区唯一那个 minimap 包（`@replit/codemirror-minimap`）有三个硬伤，逐条都致命：

1. **它每一帧都往编辑器内容区里临时插一个节点量字体再删掉**（它自己的注释写着 `TODO: … or get rid of it because it's slow`）。CodeMirror 的 DOM 观察器只盯内容区且全开监听，这种幽灵改动会被读成一次真实 DOM 变更，最终强制走一遍视图重置、**把原生选区整个重写一遍** —— 而原生选区正是 v3.2.0 换引擎保下来的东西。它在滚动时持续触发。
2. **不支持自动换行**：它按「行数 × 固定行高」算内容位置，却用真实像素定位视口框，一开自动换行两套坐标就对不上 —— 而本面板的自动换行**默认就是开的**。
3. **只绑鼠标事件**，手机上根本拖不动。

自己写的这份守三条：DOM 全挂在编辑器外层（**绝不碰内容区**）、几何全走像素（`contentHeight` / `lineBlockAtHeight`，天然兼容自动换行与代码折叠）、用 Pointer 事件一套覆盖鼠标 / 触摸 / 触控笔。绘制按缩略图的「带」循环而不是按文档行循环，**500 行和 50000 行的绘制成本完全一样**。

> **版本对比窗口里没有缩略图，两个引擎都没有。** Monaco 那边是它自己在 diff 子编辑器上无条件关掉的（源码里写死 `clonedOptions.minimap.enabled = false`），传了也会被静默覆盖。对比视图真正需要的是第 4 条那个标尺。

### 2. 缩进参考线

CodeMirror 侧同样是自建（`web/src/utils/indentGuides.ts`），线是**画在行的 CSS 背景上**的 —— 这一点是刻意的：背景是绘制、不是内容，进不了选区、也拷不走。用小部件（widget）实现会往行里塞真实 DOM 节点，那些节点会落进原生选区范围、影响手机长按选择的落点，甚至可能被系统「拷贝」抄进剪贴板。

空行会自动接上参考线（否则块中间空一行、线就断一截），空行卡在块开头时只跟到深一级，不会凭空长出一堆线。重算只在「改文档 / 滚动换视口 / 缩进单位变了」时发生，**光标移动不重算** —— 手机上每敲一下都全量重算会明显掉帧。

### 3. 空白符显示

空格画灰点、Tab 画箭头、行尾空白标底色。两个引擎的标记颜色都跟着行号色走（按编辑器底色的深浅算），所以你在系统设置里自定义了编辑器背景色，它也不会串色。

### 4. 版本对比：滚动条上的红绿标记

这条是 [#109](https://github.com/linzixuanzz/daidai-panel/issues/109) 追评里提的：「版本差异对比窗口中原本右边的拖动条，会显示代码差异行的位置，可以快速定位差异代码的位置，在新的编辑器中也没有了。」

CodeMirror 自带的只有行号旁边那条 3px 的变更条，它是**随内容滚动**的，只能告诉你当前屏幕上这几行有没有改，答不了「一共改了几处、都在哪」。本版给它补了一条总览标尺，贴在滚动条右侧：

- 每个差异块一枚刻度，**纯删红 / 纯增绿 / 修改左红右绿**；
- 颜色直接取自 CodeMirror 自己画在行号旁边那条变更条的原值，**保证两处严格同色**；
- 点刻度跳到那个差异块，点空白轨道按比例跳；
- 半透明的视口框跟着滚动移动，告诉你现在在整份 diff 的哪一段。

Monaco 那边这是原生能力，直接开着。

### 5. 点击光标后横向跟随

原文是「点击光标到某一行时默认自动滚动到该位置（横向）」。

这条只在**关掉自动换行**时才有意义（开着换行就没有横向溢出可滚）。CodeMirror 不滚不是 bug 而是它的刻意设计：只有带 `scrollIntoView` 标志的事务才滚，而**指针驱动的光标落点明确把这个标志设成 false**；键盘移动 / 输入 / 粘贴 / 撤销 / Ctrl+F 走的都是带标志的路径，本来就会滚。

所以本版只补指针这一条路径，其余一概不碰，免得和它们抢滚动位置。实现上刻意**没有**用 CodeMirror 的 `scrollIntoView` 接口 —— 那条路会一路往上遍历祖先滚动容器，最后可能把整个页面带着跳，而且 Y 轴也会动。这里只直接改编辑器自己的横向滚动位置，附带的好处是**不发事务，原生选区和手机上的选择手柄一根手指都碰不到**。

中间一大块是死区：点在视野中央不产生任何滚动，不会出现「点哪儿视图都要抖一下」。

## issue #114：双编辑器

### 引擎怎么选

编辑器工具栏齿轮菜单最下面一组（与三个视图开关用分隔线隔开）：

- **引擎：自动（Monaco / CodeMirror）** —— 括号里显示这台设备上实际会用哪个
- **引擎：CodeMirror**
- **引擎：Monaco**

切换**立即生效**，正在开着的编辑器（包括弹窗里的对比视图）会当场换掉，不用刷新页面。

### 不切过去的用户，一个字节都不下载

Monaco 是懒加载的，这一点是本版实现里花了最多力气的地方，也已经实测确认：

- **首屏增量 = 0 字节**。构建产物的 `index.html` 里只预加载 `app-core` 与 `vendor` 两个 chunk，**没有任何 Monaco 引用**。
- 引擎设成 CodeMirror 时打开脚本，网络面板里**零个** Monaco / codicon / worker 请求。
- 切到 Monaco 那一刻才按需拉取，首次约 1.0 MB（gzip）+ 138 KiB 图标字体。开 JSON 文件才会再拉 JSON 语言服务的 worker。

这里有一个**极其容易回归**的坑，写下来给后来者：Vite 的模块预加载辅助函数是个虚拟模块，不显式指定归属的话，打包器可能把它折进 Monaco 那个 chunk —— 一旦如此，**入口就变成静态依赖 Monaco**，`index.html` 里会冒出 Monaco 的预加载与样式表，懒加载当场失效。而这种劣化**构建成功、页面能用、控制台无声**。本版把它钉死在首屏 chunk 上，并在 CI 里加了一条正反双向断言守着：Monaco chunk 必须存在（防止门禁空转），且绝不能出现在 `index.html` 的预加载里。

### 没有把 v3.2.0 删掉的那套加载管线搬回来

Monaco 这次是**普通 ES 模块 + 按需 `import()`**，产物落在 `dist/assets/` 下，和别的前端资源没有区别。v3.2.0 删掉的那一整套「运行期 AMD 加载器 + 本地 `/monaco/vs` 资源探测 + CDN 兜底 + 构建后整目录拷贝」**没有回来，也不会回来**：

- 那套要往产物里塞 23 MiB / 151 个文件（本版实测只多 **4.7 MiB / 10 个文件**，构建产物从 3.88 MiB 涨到 8.59 MiB）；
- 要带回 500 多行手写的资源探测 / 三态判定 / CDN 超时兜底逻辑；
- 还要在后端静态白名单、开发服务器中间件、nginx 缓存规则、内容安全策略里各开一个口子。

本版**没有改动后端一行代码**。

### 两个引擎看起来是同一个编辑器

语法配色、行号色、当前行高亮、选区色、缩进参考线色、空白符色、搜索命中色，两边取的是同一套值 —— 换引擎不该让同一份脚本换个颜色。用户在系统设置里自定义的编辑器背景色两边都跟随。

一处**实现上的实质差别**值得记下来：CodeMirror 侧的底色是用 CSS 变量表达的，用户改色时浏览器自己就重绘了；Monaco 的主题接口只吃字面色值，所以**它必须在每一次外观变化时重新定义主题**，哪怕只是改了背景色、没有切明暗。

## issue #109 追评：环境变量禁用行整行弱化

原话是「禁用掉的环境变量，把它的各项值（名称、值、备注等）的字体颜色降低透明度，更突出该条环境变量已被禁用的状态，**但是不确定这样改是否会影响这条变量的可读性**」。

**那句担心是对的，所以本版没有用透明度。** 实测数据（WCAG 相对亮度，明色模式行底 `#fff`）：

| 元素 | 基线对比度 |
|---|---|
| 名称（品牌蓝 `#409eff`） | 2.78:1 ← 本来就不到 AA 的 4.5:1 |
| 值（`#303133`） | 13.02:1 |
| 备注 / 更新时间（`#606266`） | 6.11:1 |

整行叠透明度之后：

| 透明度 | 名称 | 备注 |
|---|---|---|
| 0.85 | 8.08 | **4.33** ← 已破线 |
| 0.90 | 9.51 | 4.84 ← 但到这一档人眼已经看不出「淡了」 |

也就是**「看得出被调暗」和「读得清」在明色下不能同时成立**。

改用「**浅底 + 文本降一档语义令牌**」：弱化感来自「彩色 → 中性灰」的色相变化，而不是变淡。名称从品牌蓝换成中性灰之后对比度**反而从 2.78 升到 5.85**，值从近黑降一档到同样的中性灰，备注和更新时间本来就在这一档、触底不动。红绿状态点与操作栏的「启用」按钮保持原样，它们仍是主要的状态载体。

顺带一个净收益：红/绿状态点是最典型的色觉障碍撞色对，「整行变灰」等于给它补上了一条**非颜色的**状态通道。

还有一条纯技术原因不能用整行透明度：环境变量页的操作列是固定列，透明度小于 1 会造出新的层叠上下文，把固定列的层级关系打乱。

「又置顶又禁用」的行仍然显示置顶的橙色底 —— 置顶是用户主动标记的，语义优先级更高。

## 本版没做的

**代码格式检查（lint）。** 这条在 #109 的追评里出现过，#114 重新列 5 条时没有再列，本版按 #114 的清单做，没有做它。它和上面五项不是一个量级：要给每种语言引一套检查器（JS/TS 一套、Python 一套、Shell 一套），还要决定规则集从哪来、怎么让用户配、错误怎么在两个引擎上一致地呈现。想要的话请单开一条 issue 说明具体期望（比如「只要语法错误提示」还是「要 ESLint 规则」），差别很大。

**多光标 / 列选，在 CodeMirror 引擎下仍然没有。** 理由与 v3.2.0 相同：它和「保住原生选区」是同一枚硬币的两面。**但从本版起，桌面端切到 Monaco 就有了** —— 这也正是双引擎想解决的问题。

## 升级方式

- Docker：拉取新镜像重启；**自建 nginx 的请同步 `docker/nginx.conf` 的 `ttf` 那一行**。
- Magisk / Debian 模块：**面板内一键更新即可**，本版没有改动模块外壳脚本，不需要重刷 ZIP。
- Windows：替换可执行文件与 `web` 目录。

升级后如果桌面端想回到 v3.2.1 的观感，在编辑器齿轮菜单里把引擎锁成 **CodeMirror** 即可，五项功能一项不少。

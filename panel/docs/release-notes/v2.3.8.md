# v2.3.8
<!-- release-title: 配置文件多行变量与运行兼容优化 -->

## 版本概览

`v2.3.8` 是 `v2.3.7` 之后的维护版本。本轮改善 `config.sh` 多行变量、特殊脚本退出码和 Windows Python 时区兼容性；后续完成的同版本问题会继续追加到本说明。

## 修复

- **修复配置文件多行变量只读取首行**：`config.sh` 现在支持 `export KEY='...'` 和 `export KEY="..."` 的跨行内容。例如在一个变量里按四行填写四个账号后，Node.js 的 `process.env.KEY`、Python 的 `os.environ` 和 Shell 任务都会读到保留换行的完整值，不再只剩第一个账号。
- **修正同名变量优先级**：环境变量页面中的同名变量继续优先于 `config.sh`，与配置文件页的说明保持一致。
- **兼容特殊脚本的非零成功码**：任务“高级设置”新增“成功退出码”，默认仍为 `0`。对于业务已经完成但固定返回 `1` 的历史脚本，可单独填写 `0,1`，面板会统一按成功状态记录日志、统计和通知，同时保留真实退出码；超时、启动错误和主动停止不会被误判为成功。
- **修复 Windows Python 日志慢 7 小时**：系统设置选择 `Asia/Shanghai` 后，Python 脚本和 `python -m` 模块现在都会按北京时间运行。面板会在 Windows Python 启动时自动处理 IANA 与 CRT 时区格式差异；Node.js、Linux、Docker 和面具版继续使用原有 IANA 时区，不受影响。

## 升级说明

- 多账号内容可以继续用单引号或双引号包住，并在引号内直接换行，不需要手动改成 `&` 或字面量 `\n`。
- 为了保持安全边界，面板只解析配置文件中的变量赋值，不会执行其中的 Shell 命令、函数或命令替换。
- 普通任务无需修改“成功退出码”。仅在确认脚本把 `1` 当作正常完成结果时配置 `0,1`，不要根据日志中的“结束”字样盲目放宽。
- Windows 用户无需修改现有时区设置，继续在系统设置中选择 `Asia/Shanghai` 即可；Python 脚本读取到的 `TZ` 仍是这个标准名称。

## 验证

- 后端回归测试：覆盖单引号多行、双引号多行、单行值、异常未闭合值、同名变量优先级与 Node.js `process.env` 实际读取。
- 任务结算回归测试：覆盖旧 SQLite 自动补列、默认退出码、非零成功码、非法配置、任务编辑/复制/导入导出，以及真实退出码 `1` 的成功状态和日志标记。
- 时区回归测试：覆盖 IANA 到 Windows Python POSIX 偏移的转换，以及真实 Python 脚本、`python -m` 模块和 Node.js 子进程的北京时间结果。
- 最终发布前执行：`go test ./...`、`npm run build` 与 `scripts/release-preflight.ps1 -Version 2.3.8`。

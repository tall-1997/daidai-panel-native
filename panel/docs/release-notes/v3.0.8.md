## 版本概览

`v3.0.8` 分两条线：

- **交互体验**：补齐一整套动效交互组件，并铺到全部 15 个页面。同时修掉了三处**构建全绿、控制台无声**的动效缺陷 —— 其中一处让全站 48 个弹窗从来就没有过进出场动画，另一处让「全站直角」这个设计约定从 v3.0.0 起就没真正生效过。
- **功能修复**：两个来自用户反馈的 issue，实时日志丢最后几秒（[#102](https://github.com/linzixuanzz/daidai-panel/issues/102)）、Magisk Debian 版 SSH 连不上（[#100](https://github.com/linzixuanzz/daidai-panel/issues/100)）。

> ⚠️ **Magisk 用户注意**：#100 的修复动的是**模块外壳脚本**，面板内的一键升级只替换 `daidai-server` / `ddp` / `web`，**覆盖不到**。要拿到这项修复必须**重刷模块 ZIP**。
> 其余改动（含 #102）随正常更新即可。

## 修复：实时日志显示不全，丢掉最后几秒（#102）

用户报的现象是「面板日志明显缺最后几秒，但脚本自己写出来的 log 文件是完整的」，还给了两条关键线索：「有些脚本就可以显示全」「脚本末端加 5 秒延时再结束，也可能能显示全」。

> **根因：读输出的协程和「等待进程退出」是并发跑的，而 `cmd.Wait()` 会在进程退出后立刻关闭输出管道。**
>
> Go 的 `os/exec` 对 `StdoutPipe` 有一条明确约定：
>
> > Wait will close the pipe after seeing the command exit ... it is incorrect to call Wait before all reads from the pipe have completed.
>
> 原来的写法正是「先 Wait、再等读完」。进程一退，管道被关，里面还没读完的数据连同 fd 一起消失。

三条现象全部对得上：

- **「最后几秒不显示」** —— 尾部数据还在管道里没读完
- **「有些脚本能显示全」** —— 输出少、读得快，抢在关闭前读完了
- **「加 5 秒延时就能显示全」** —— 延时把进程退出推后，给了读取时间

更麻烦的是它**完全静默**：读协程拿到的错误是 `read |0: file already closed`，恰好落在代码里的「良性管道错误」白名单中被吞掉。日志里没有任何报错，执行结果还照样显示「成功」——不去和脚本自己写的 log 逐行对比，根本发现不了。

**影响范围是 3 处**，不止任务执行：

| 位置 | 说明 |
|---|---|
| `runSingleCommand` | 定时任务执行走这里，#102 的直接原因 |
| 钩子脚本（带超时） | 更严重：读协程连等待完成用的 channel 都没有 |
| `RunHookScript` | 同上 |

（订阅拉取那条路径 `runCmdWithCallback` 反倒是写对的 —— 它是同步读完才 `Wait`，本次以它为范本。）

现在把「**先把管道读干净、再等待进程退出**」抽成一个函数 `pumpAndWait`，三个调用点统一走它。超时分支先杀进程组再等排空 —— 进程一死写端就关，读端必然 EOF，不会卡住。

**验证数据**（本地起真实面板 + 一个输出 2000 行后立刻退出的 Python 脚本）：

| | 结果 |
|---|---|
| 修复前 | 只留下 **23 行**，丢了 **98.85%** |
| 修复后 | **2000 行一行不少**，末行正确 |

修复前那次的日志末尾照样写着「执行结束 退出码 0」——面板认为任务成功，用户看不出被截断过。

回归测试用测试二进制自己当子进程（跨平台，不依赖外部解释器），并在输出回调里故意放慢读取，把竞态放大成**确定性**失败：把那两行顺序换回去，测试立刻红，报的正是 `read |0: file already closed`。

> **顺带澄清一处不是 bug 的地方**：实时日志的 SSE 广播在订阅通道满时会丢弃。那是**有意**的 —— 换成阻塞发送，一个卡住的浏览器连接就能拖死整个任务执行。落盘是同步的，前端收到结束事件后会重新拉完整日志覆盖，属于最终一致。
>
> 判据写进代码注释了：**刷新后还缺** = 源头丢（真 bug）；**只有运行中缺、结束后完整** = 广播丢（符合预期）。

## 修复：Magisk Debian 版 SSH 连不上（#100）

`v3.0.7` 修过一次，用户重刷后仍然「输完密码就断开」。从他的 `sshd.log` 能直接读出根因：

```
Accepted password for root from 192.168.1.2 port 45968 ssh2   ← 密码是对的，认证已经过了
sh: 1: cannot create /run/motd.dynamic.new: Required key not available
PAM: pam_open_session(): Error in service module              ← 卡在这一步
```

> **根因：认证通过之后 sshd 要「开会话」，PAM 的 session 栈里只要有一个必需模块出错，整条 `pam_open_session` 就失败，sshd 随即断开。**

`v3.0.7` 修的是 `pam_loginuid`（它要写 `/proc/self/loginuid`，容器里没权限）。用户日志里已经没有那个报错，说明那一处**确实修好了**；但现在卡在了下一个模块 `pam_motd` —— 它要跑 `/etc/update-motd.d/` 里的脚本、往 `/run` 写文件，在那台机器上返回了 `ENOKEY`。

**逐个模块 patch 是打地鼠**：`pam_loginuid` 要写 `/proc`、`pam_keyinit` 要建内核 keyring、`pam_motd` 要写 `/run`、`pam_limits` 要 `setrlimit`、`common-session` 里的 systemd 模块要连 D-Bus —— 在 Android 的 chroot 环境里每一个都可能失败，修好一个、下一台机器又冒一个新的。

这一版改成：**保留 PAM 负责密码校验**（`auth` / `account` 栈完全不动），只把 **session 栈整段**替换成恒定成功的 `session required pam_permit.so`，并一并删掉 `@include common-session`（里面的必需模块同样能掐断会话）。这样无论哪个模块在某台机器上会失败，都不再有机会掐断会话。

> **为什么不直接 `UsePAM no`**：Debian 有过「构建时没链上 crypt，`UsePAM=no` 下正确密码也一律被拒」的先例（Debian bug #1142354）。那会把故障从「连上就断」升级成「根本登不上」，更糟。仓库里有门禁守着这一条。

细节：

- 改前备份 `/etc/pam.d/sshd.daidai-bak`（只备份一次，不会把改过的版本当成原始版本覆盖上去）
- 幂等 —— `service.sh` 每次开机都跑，已替换过就跳过
- `service.sh`（管每次开机）与 `customize.sh`（管新装）两处同步

代价是没有 motd、没有 `pam_limits` 的资源限制、没有 `pam_env`。面板场景（root 进容器跑脚本）这几样都不需要。

**排障日志也加强了**：`service.log` 里原来那行 `[ssh] usepam=<grep 计数>` 换成了 `[ssh] effective=<sshd -T 的输出>`。grep 配置文件只能证明「我们写进去了」，证明不了「sshd 认了」—— drop-in 覆盖、`Match` 块作用域、语法错误回落默认值，这三种情况 grep 都看不出来；`sshd -T` 是 sshd 自己解析完的结果，是唯一权威的判据。

> ⚠️ **这一项没有在真机上验证过**。脚本逻辑本身（配置替换是否正确、是否幂等、认证相关配置有没有被误删）在本地用真实的 Debian `pam.d/sshd` 样例逐条验证过，但 PAM 在具体机型上的实际行为、`/run` 返回 `ENOKEY` 的成因，需要用户实测回报。
> 刷完之后无论成败，欢迎把 `/data/adb/daidai/sshd.log` 与 `service.log` 贴到 issue 里。

## 新增：动画交互组件

这一版补齐了七类动效交互组件，并铺到全部 15 个业务页面 + 主布局。

视觉上**沿用面板既有的「全屏纯扁平直角」基调** —— 没有引入圆角、阴影和装饰渐变，层次仍然靠 `1px` 边框与底色反差表达，动效时长统一走设计令牌，系统开启「减少动态效果」时自动降级。

| 组件 | 说明 |
|---|---|
| **角标** | 侧栏菜单实时角标：运行中任务、今日失败日志、拉取失败的订阅、安装失败/进行中的依赖、有新版本。数字变化做翻牌，收起侧栏时退化成图标右上角一个方点 |
| **轻提示** | 全站几百处提示的**统一观感与动效**。左缘 3px 语义色实心条替代原来「浅底 + 同色图标」的弱区分；停留时长按「这条要不要读完」分档，不再一律 3 秒 |
| **带操作的轻提示** | 把打断式弹窗降级成非阻塞提示 + 一个后续入口。落点：通知渠道测试失败带「查看详情」、更新/恢复超时带「立即刷新」、重置用户密码带「复制密码」 |
| **Select** | 下拉面板从 `scaleY` 卷帘改成淡入 + 轻微上移，朝上弹出时位移自动反向。全站 60+ 处一次受益 |
| **Multi-select** | 标签化多选 + 「已选 N 项 · 最多 M 项」计数 + 一键清空。到上限后**未选中的项置灰**（而不是静默忽略点击），已选中的仍可点，不会被锁死 |
| **Split Button** | 主操作直接执行 + 右侧箭头展开更多。铺到 7 个页面，操作列宽度普遍收窄 30~50%。**危险操作一律进菜单并标红加分隔线**，绝不放在「点了就执行」的主体上 |
| **日期范围** | 快捷项（今天 / 昨天 / 近 7 天 / 近 30 天）+ 「共 N 天」汇总行 + 禁选未来日期。**执行日志页新增按时间筛选**（服务端同步支持 `start_time` / `end_time`） |

配套的还有：

- **执行日志按时间筛选**：这是本次唯一的新功能。服务端按 `created_at` 闭区间过滤 —— 与列表里显示的那一列、与侧栏「今日失败」角标是同一个口径，不会出现「列表写着 8-23，按 8-23 筛却少了几条」
- **状态切换过渡**：轮询/SSE 中会自己流转的状态标签（任务运行中→成功/失败、依赖排队中→安装中→已装好）之前是硬切，现在有交叉淡入，"变了"这件事看得见
- **批量操作条进出场**：勾选后凭空冒出一排按钮会把整行顶得跳一下，现在是淡入淡出
- **脚本管理与配置文件页补上入场动效**：这两页此前是全站仅有的两个完全没有入场动效的页面

> 内部还加了一个动效预览页 `/dev/motion`（不在侧栏菜单里，也不参与预加载），七类组件的全部状态排在一页，方便验收。

## 修复：三处静默失效的动效缺陷

这三处的共同点是**构建全绿、控制台无声、类型检查也发现不了**，只能靠浏览器实测才会现形。

### 1. 全站 48 个弹窗，从来就没有过进出场动画

样式里引用了四个关键帧 `dd-dialog-surface-in` / `-out`、`dd-dialog-overlay-in` / `-out`，但**全仓库一个 `@keyframes dd-dialog-*` 都没有**。

CSS 里 `animation-name` 指向不存在的关键帧是完全合法的 —— 不报错、不告警，只是什么都不发生。而那几条引用还带了 `!important`，把 Element Plus 原生的 `dialog-fade` 一并压掉了。于是弹窗既没有自己的动画，也没有 EP 的动画，一直是瞬现瞬消。

### 2. 弹窗动画只在第一次打开时跑

补齐关键帧之后又发现：动画挂在 `.el-dialog` 上，而它**不是** `<transition>` 的作用元素；EP 的 `el-dialog` 默认 `destroy-on-close=false`，第二次打开同一个弹窗时 DOM 被复用，动画不会重放。

表现是「第一次打开有动效，之后就只剩遮罩淡入」，很容易被当成错觉。改挂到 `.el-overlay-dialog` 上（它在 transition 的作用域里）之后，每次打开都会重放。

进场刻意不加 `fill-mode: both` —— 残留的 `transform` 会成为 Monaco 编辑器内部浮层的包含块，让代码补全菜单飘到错误位置。

### 3. 「全站直角」从 v3.0.0 起就没真正生效过

`:root` 里写了 `--el-border-radius-base: 0`，但 Element Plus 的 `base.css` 里也有一条 `:root { --el-border-radius-base: 4px }` —— **两者特异性完全相同**，而组件样式是随页面按需注入的、必然排在入口样式之后，同特异性后来者赢。

于是那三行圆角归零一直是**死的**，运行时实际值是 `4px`。凡是没有被单独写死 `border-radius: 0` 的地方都在吃这个令牌：

| 命中点 | 实际圆角 |
|---|---|
| **全站 `size="small"` 的按钮**（表格操作列的按钮几乎都是） | 3px |
| 下拉面板 / 下拉菜单 / 日期选择器输入框 | 4px |

一个普通页面上实测能数出 **39 处**非零圆角。加上 `!important` 之后归零，实测 14 个页面逐页复查全部为 **0 处**。

## 其他修复与改进

- **执行日志 / 用户管理 / 通知渠道 / 环境变量** 四页的操作列按钮组没有清掉 Element Plus 自带的 `.el-button + .el-button { margin-left: 12px }`，与 flex `gap` 叠加。按钮组一旦超出列宽，单元格会变成可滚动容器，点右侧按钮时整行左移**且不会自动复位**
- **Open API 的操作列没有固定在右侧**：这张表列多，1249px 视口下实测横向溢出 323px，操作列整个被挤出可视区，得先横向滚动才点得到
- **仪表盘给表格每一行做了错落入场**：违反项目自己的约定（行多会卡），而且那张表是轮询刷新的，每次刷新都会整表重放，表现为规律性闪烁
- **通知渠道删除失败时界面零反馈**：`catch` 把「用户点取消」和「删除接口真的失败了」混成了一件事，删除失败时渠道还在列表里、却没有任何提示
- **「减少动态效果」下的降级不完整**：只压了动画时长、没压延迟。配合 `fill-mode: both` 时元素会先隐身整个延迟再瞬现，比原来的平滑淡入**更刺眼**
- **时间显示统一**：全站原本有 8 种写法，同一个「创建时间」在不同页面长得不一样（跟浏览器语言走的 `8/23/2026, 3:04:05 PM`、带「下午」的、只有日期没有时间的）。现在统一为 `2026-08-23 15:04:05` —— 等宽、可排序、月日恒为两位，表格里上下行对得齐。会话管理这类「看新旧」的场景改用「3 分钟前」这样的相对时间；登录日志这类审计表坚持绝对时间
- **清掉一份 209 行的死样式表**：22 个工具类全部零引用，里面还留着玻璃拟态、写死时长的过渡和暗色下不跟随的硬编码颜色 —— 留着就是隐患，谁顺手复用一个类名就等于引入一处违规

## 升级方式

| 部署方式 | 操作 |
|---|---|
| Docker | 重新拉取镜像后重建容器 |
| Magisk 模块 | **重刷模块 ZIP**（#100 的修复在模块外壳脚本里，面板内一键升级覆盖不到） |
| 裸机 / Windows | 面板内一键更新，或下载新版二进制替换 |

## 版本概览

`v3.1.0` 依旧是**用户反馈驱动**的版本，三条来自两个 issue，另有一条来自开发过程中的追加反馈：

- [#105](https://github.com/linzixuanzz/daidai-panel/issues/105)（正文 2 条 + 追评 1 条）：新增接口希望加幂等与唯一键校验（「环境变量网络慢点或者点的快会创建多个一样的」）、以及「最新版呆呆样式变方了，越来越丑」，追评补充「button、tag、card 等都变方了」。
- [#107](https://github.com/linzixuanzz/daidai-panel/issues/107)（1 条）：「apk 建议增加页数」，任务一多就卡。
- 开发过程中的追加反馈（1 条）：「PushPlus 推送好像官方又更新了新的推送，例如可以推送到 QQ 上了」——查证属实，官方新增了一个免费的 QQ 机器人渠道。

**这一版的重头戏是根因取证，而且来自 issue 的三条里有两条的真正病根与用户的表述不同**：幂等问题的根子不在唯一键、卡顿问题的根子不在分页；剩下那条「变方了」则是用户的感受完全真实、但触发点其实是上一版的一次修复。三处都在下面各自的小节里摊开讲。

其中**一条是行为变更**（老库里的重名资源会被自动改名），见升级须知。本版有 APP 侧改动，需要配套 `v1.3.3`。

感谢 [@leishenws](https://github.com/leishenws) 与 [@a65101855](https://github.com/a65101855) 提的 issue。

## 升级须知

### 1. 老库里的重名资源会在启动时被自动改名（不会删任何数据）

本版给**语义上确实唯一**的 5 类资源加了数据库唯一索引。老库里如果已经存在重名记录，启动迁移会先把重复项**改名**再建索引：

| 受影响的资源 | 唯一范围 |
|---|---|
| 通知渠道 | 全局同名 |
| SSH 密钥 | 全局同名 |
| 任务视图 | 全局同名 |
| OpenAPI 应用 | 全局同名 |
| 平台令牌 | **同一个平台下**同名 |

改名规则是：同一唯一键下按 id 升序**保留第一条**，其余依次追加 ` (2)`、` (3)`……；候选名字本身已被占用（老库里可能真有一条就叫「渠道 (2)」）就继续往后递增。**全程只改名字，不删除任何一条记录**，每改一条都会往面板日志写一行 `唯一约束迁移：检测到重名的…，已把 id=… 的「…」改名为「…」`。重复执行是幂等的。

> 这一步排在建表迁移**之前**是必须的。反过来的话，老库撞上新加的唯一索引会让 `AutoMigrate` 失败，**面板直接起不来**。

**恢复 `v3.0.10` 及更早导出的备份时同理。** 归档里的数据不会随升级被清洗——你在 `v3.0.10` 连点创建出的两条都叫「推送」的通知渠道（当时完全合法）会原样躺在备份里，恢复时会按同一套规则改名，并在面板日志留下 `恢复备份：归档里存在重名的…，已改名为「…」`。青龙备份导入走的是同一条恢复管线，行为一致。

> 没有这一步的话，老备份会因为撞唯一索引导致**整次恢复回滚**——那意味着用户手上那份备份**永远恢复不了**。这个代价比「名字后面多个 (2)」大得多。

**环境变量不在这张表里，而且是刻意的**，理由见下面第一节。

### 2. 界面圆角默认仍是直角，升级后观感零变化

新增的「界面圆角」默认值是**直角**，与升级前**逐像素一致**，不需要任何手工操作。想要圆角的话：**系统设置 → 其他配置 → 界面圆角**，切到「圆角」即可，**即时生效、不用刷新**。

> 这一项**仅网页端生效，APP 不受影响**。APP 的设置页是 schema 驱动的，会跟着服务端注册表把这个开关渲染出来，但点了不会有任何效果——所以它的说明文案里明写了这句话，免得被当成 APP 的 bug。

## 修复：连点或网络慢时会创建出多条相同记录（#105）

用户报的现象是「环境变量网络慢点、或者点得快一点，就会创建出多个一模一样的」，并建议**所有新增接口都加幂等与唯一键校验**。

诉求是对的，但**病根和药方都不在用户猜的那个位置**，所以这一节先把取证摊开。

> **根因一：环境变量允许同名是有意设计，给它加唯一键会直接废掉多账号能力。**

三条独立证据都指向同一个结论：

| 证据 | 内容 |
|---|---|
| `server/handler/env.go` 的原文注释 | 「青龙风格：新建一律纯 insert。同 name 允许多条（多账号场景），运行时按 name 分组再用 `&` 拼接暴露给脚本」 |
| `server/database/database.go` | `dropEnvVarUniqueIndex()` **每次启动都会主动 DROP** 掉历史库里残留的那个唯一索引 |
| 前端 | 「复制同名变量」是一个一等公民入口，不是误操作 |

引入这套语义的是 `v2.0.8` 的提交 `911c13f`。同一个 `JD_COOKIE` 存 N 条、运行时自动拼成 `a&b&c` 交给脚本，正是青龙用户的主力用法。**给它加唯一键等于一刀砍掉多账号**，所以本版明确不加。

> **根因二：真正的问题在前端——全站约 25 处创建表单里，17 处对连点零防护。**

那 17 处的按钮既没有 `:loading` 也没有 `:disabled`，父组件 `await` 请求期间弹窗还开着。网络越慢窗口越大，点第二下就是第二个请求——**服务端收到的是两个完全合法、内容相同的创建请求，任何后端校验都只能靠唯一键去挡，而环境变量恰恰不能加唯一键**。

### 这一版的改法

| | 改动 |
|---|---|
| 前端（主力） | 17 处创建入口全部补上在途锁：环境变量新建 / 导入 / 批量分组 / 批量重命名、定时任务新建、复制任务、任务视图、通知渠道、订阅、SSH 密钥、用户、OpenAPI 应用、脚本新建文件 / 新建目录 / 上传、IP 白名单、创建备份 |
| 后端（唯一索引） | 5 类语义上确实唯一的资源加数据库唯一索引 + 友好的中文报错：通知渠道名、SSH 密钥名、任务视图名、OpenAPI 应用名、平台令牌（同平台下的名字） |
| 后端（先查后插） | 订阅与依赖只做「先查后插」，**刻意不加**唯一索引 |
| 顺带 | 修掉三处 `Create` 和一处 `Updates` 没接错误的静默吞错 |

**在途锁的位置是有讲究的**：置位一律放在**所有早退校验之后、`await` 之前**。放在函数开头的话，表单校验不通过直接 return，锁就再也解不开，按钮永久转圈。复位一律在 `finally`，请求抛错也能恢复。

**回车提交是一条独立的旁路，单独补了闸。** 脚本页「新建文件 / 新建目录」的输入框挂着回车提交——按钮上的 `loading` 只能挡住鼠标点击，**连按回车会直接绕过它**。环境变量的批量重命名同理。这两处在提交函数入口另加了一道在途闸。

**订阅与依赖为什么不加唯一索引**：同一个仓库以不同分支、不同子目录、或不同保存目录订阅两次是**完全合法**的用法，按 URL 建唯一索引会把它挡死。所以订阅的判重键是「地址 + 分支 + 子目录 + 保存目录 + 别名」五者全同才算重复。依赖侧顺带补齐了一处不对称：以前只有 Python 分支做先查后插，nodejs / linux 连点两次就会重复提交同一个包的安装，现在按「类型 + 名称」精确匹配统一了。

> **这里必须如实说明：先查后插挡得住连点，但挡不住真正的并发。**
>
> 两个请求几乎同时到达时，可能双双查不到、再双双插入。**这两类资源的主力防线仍然是前端按钮锁**，后端只是补刀。加了唯一索引的那 5 类才是真正意义上的「后端兜底」。不要把这一版读成「所有创建接口都已经彻底防重」。

**顺带修的静默吞错**里有一处值得单独点名：**2FA 的 secret 写库没有接错误**。它的失败模式是——你扫完二维码、输入验证码，**永远对不上**，因为库里压根没写进那条 secret，而界面上没有任何报错。另外三处同样是写库失败却一路返回成功。

## 新增：界面圆角可切换（#105）

用户说「最新版呆呆样式变方了，越来越丑」，追评补充「button、tag、card 等都变方了」。

这条的取证结论比较意外，值得完整讲一遍：**用户的感受 100% 真实，但让他察觉到的那次变化，其实是一次修复。**

> **根因：`v3.0.0` 定的「纯扁平直角」基调，有一大半在 `v3.0.8` 之前根本没生效过。**

**时间线**

| 版本 | 发生了什么 |
|---|---|
| `v3.0.0`（`b302561`） | 定下「全屏铺满 + 纯扁平直角」的设计基调，对标青龙那类工具型后台。标签和卡片通过组件私有令牌**当场就方了** |
| `v3.0.0` ~ `v3.0.7` | **按钮一路都是 4px 圆角**（small 档 3px）——`:root` 里那条圆角令牌覆盖是**死的** |
| `v3.0.8`（`8c4514f`） | 补上 `!important`，按钮**第一次真正方掉** |

那条覆盖为什么是死的：Element Plus 在自己的 `:root` 里也声明了同名令牌，而组件样式是**懒注入**的、必然排在入口样式之后——同特异性、后来者赢。也就是说面板写的那条覆盖从落地那天起就没赢过。

⇒ 用户看到的「最新版变方了」，正是 `v3.0.8` 那次修复的副作用。**这既不是审美倒退，也不是 bug，而是一个「意图与实现终于对上」的时刻恰好落在了用户的升级节点上。**

既然直角是有意为之、而反馈也是真实的，那这件事的正解就不是「改回去」，而是**做成可选项**。

### 形态

**系统设置 → 其他配置 → 界面圆角**，两档：

| 选项 | 效果 |
|---|---|
| **直角**（默认） | 扁平工具型，与升级前完全一致 |
| 圆角 | 各控件与卡片带圆角 |

切换**即时生效**（不用刷新），并且用本机缓存做了**首屏防闪形**——首屏拿到服务端配置之前先按上次的选择渲染。**形状跳变比闪色刺眼得多**：闪色只是颜色变一下，闪形状会让整页元素的轮廓在你眼皮底下重排一次。

### 为什么要动 325 处

只把令牌改活是**不够**的。为此把全站圆角**刻度化**成三档设计令牌：

| 档位 | 圆角模式 | 直角模式 | 用在哪 |
|---|---|---|---|
| 控件档 `--dd-radius-control` | 6px | 0 | 按钮、输入框、标签、分段控件 |
| 表面档 `--dd-radius-surface` | 10px | 0 | 卡片、弹窗、浮层、面板 |
| 胶囊档 `--dd-radius-pill` | 999px | 0 | 需要完全药丸化的元素 |

改动覆盖 `global.scss` 里 **12 组** Element Plus 兜底、**10 个**通用类，以及 **51 个页面文件里的 325 处**硬编码圆角值。那 325 处写的是字面量、不吃令牌——不改的话切到圆角模式会得到**一半圆一半方**的花脸，比全方还难看。

### 顺带修掉两条从 `v3.0.x` 起就存在的静默失效

这两条属于同一类问题（写了覆盖但没生效），借这次刻度化一起收掉：

- **`ElMessageBox` 弹窗一直是 4px 圆角。** 它的圆角变量被 Element Plus 声明在**组件根元素**上而不是 `:root`，所以面板写在 `:root` 里的那条覆盖是彻头彻尾的死 CSS，从来没有命中过。
- **全站浮层（tooltip / 下拉 / 日期面板）的那条覆盖漏了 `!important`。** 病因和上面按钮那条一模一样，只是 `v3.0.8` 补 `!important` 时漏掉了它。

## 修复：开关、状态灯、头像等被一刀切削平的形状（#105）

这一批用户没有单独提，但和上一节是同一件事的另一面：`v3.0.0` 一刀切方化时，误伤了一批**形状本身承载语义或可供性**的元素。

> **判据：如果把一个元素变方会让人分不清它是什么、或者不知道能对它做什么，那它的形状就不是装饰。**

这个判据在 `v3.0.0` 时已经用过——加载圆弧和单选圆点当时就进了白名单。本版把同类的另外几种补进去，并且**两种模式下都固定圆形**（不随「界面圆角」开关变化）：

| 类别 | 处数 | 方化之后的问题 |
|---|---|---|
| 开关（轨道与滑块） | 33 处 | 方轨道 + 方滑块与复选框难以区分 |
| 状态灯 | 约 9 处 | 运行中呼吸点、侧栏收起态的角标点、接口文档状态点、日志行状态点、拉取状态色标等，方了就不像「灯」 |
| 头像 | 约 12 处 | 顶栏与个人页头像、通知渠道 / OpenAPI 应用 / 依赖的首字母头像，以及**赞助墙上直接渲染的 GitHub 头像**——那些图本身按圆形构图，方切后观感最差 |
| 标签的图标底与关闭键 | — | 关闭键方了之后不像可点击的「×」 |

### 顺带立的一条新规则：≤12px 的小盒子不能吃控件档

CSS 的圆角收缩规则会在半径超过盒子边长一半时按比例夹住。**6px 半径落在 10×10 或 8×8 的盒子上会被夹成正圆**——于是「用直角把分类色标和状态灯区分开」这个意图，在圆角模式下会自动失效，两种东西长得一模一样。

所以：

- **分类色标固定 2px**：分组色点、文件类型色标、图例色块。它们表达的是「归属于某一类」，不是「某个东西正在运行」。
- **复选框按比例缩到 2px**（`--dd-radius-control` 的三分之一）。14px 的复选框吃 6px 会被圆到接近单选圆点，削弱「**方 = 多选 / 圆 = 单选**」这条几乎是肌肉记忆的可供性。

> 直角档的控件令牌是**无单位的 `0`**，所以复选框那个 `calc(… / 3)` 在直角模式下算出来仍然是 0，不会因为除法引入意外的单位。

## 新增：PushPlus 支持官方新出的 QQ 机器人渠道

这一条不来自 issue，是本轮开发过程中的一条追加反馈：「PushPlus 推送好像官方又更新了新的推送，例如可以推送到 QQ 上了」。查证属实，顺手一并做了。

> **变化点：官方在 `channel` 参数里新增了「QQ 机器人」，而面板此前的 9 个渠道选项里没有它。**

**系统设置 → 通知渠道 → PushPlus → 发送渠道**，下拉里现在多出一项「QQ 机器人 (qq)」，**免费**，个人消息与群消息都支持。

配置方式：PushPlus 个人中心 → 渠道配置 → 选「QQ 机器人」→ 用 QQ 扫码把机器人加为好友（自动绑定失败时，把绑定码私聊发给机器人）。

### 「渠道编码」这一栏的填法是这条里最容易踩的坑

| 发给谁 | 渠道编码 |
|---|---|
| 个人 | **留空** |
| 群 | 填该群的**配置编码** |

也就是说**填了就会被当成群消息**。要发到群里还得先在 PushPlus 的渠道配置里给那个群单独建一条群配置，并把机器人拉进群、允许它主动发消息。

其余几条官方限制一并列在这里：

| 限制 | 内容 |
|---|---|
| 群消息 | 不能同时再填「群组编码」 |
| 每日请求上限 | 实名用户 200 次、会员 1000 次 |
| 单条内容 | 约 2000 字 |
| 模板 | 官方推荐 `txt` 或 `markdown`——**QQ 的 Markdown 不支持代码块和 HTML** |

除了每日上限，其余几条都已经写进面板里那两栏的输入提示——模板建议与 2000 字在「发送渠道」，群消息不能带群组编码在「渠道编码」，配的时候不用回头翻官方文档。

### 顺带把 PushPlus 推送改走了 HTTPS

面板此前写死的是 `http://www.pushplus.plus/send`（官方文档至今也是这么写的），意味着**用户的 PushPlus token 是明文过网的**。

实测：对 `https://` 与 `http://` 两个地址各打了一发同样的请求，**都返回 HTTP 200 且响应体逐字节相同**（`{"code":903,...用户令牌不正确}`）⇒ HTTPS 通道可用，已改成 https。

这是纯安全改进，**对用户没有任何可感知的行为变化**，所以没有进升级须知。

### 官方另外新增的 7 个模板刻意没有补进来

官方现在的模板全集是 html / txt / json / markdown / cloudMonitor / jenkins / route / pay / form / doc / excel，面板只保留前 4 个：

| 没补的模板 | 理由 |
|---|---|
| cloudMonitor / jenkins / route / pay | 特定场景的专用排版，套在任务执行结果上只会让消息变形 |
| form / doc / excel | 需要额外的 `pushId` 参数，而面板没有这个概念，用户选了必然发送失败 |

**摆进下拉框等于挖坑**，所以这条理由已经写进代码注释，防止后人「补齐」。

## 优化：APP 任务页改为虚拟化渲染，任务再多也不卡（#107）

用户的标题写的是「apk 建议增加页数」，正文补充「任务页太多就卡」。

**取证结论是：分页早就有了，卡的原因是渲染。这一点必须讲清楚，否则改错方向。**

> **根因一：服务端分页不是缺失的，缺的是 APP 没在用。**

`GET /api/tasks` **早就是一个完整的服务端分页接口**：支持 `page` / `page_size` / 关键词 / 状态 / 标签 / 排序，默认每页 20、上限 100。网页端一直走的就是真正的服务端分页。

卡的只有 APP：它**硬编码要求服务端返回全量任务**，然后用**非虚拟化**的方式把它们全画出来。

> **根因二：分组结构把列表的惰性机制整个旁路掉了。**

APP 把每个分组包进一个 `Column`，而 **`Column` 没有惰性布局**——它的所有孩子都会被无条件构建并完成布局，不管在不在屏幕上。每张任务卡还是几十个 widget 起步。

**最糟的恰恰是从没建过分组的用户**：整个列表只有 **1 个孩子**（一个装着全部任务卡的 `Column`），列表自身的惰性机制**完全失效**，等价于一次性构建全部任务。

⇒ **只做分页不修渲染是白做一轮**：每页 100 条照样要建 100 张重卡。反过来，虚拟化之后即使保持全量拉取，滚动也能恢复流畅。所以本版**全部改动都在 APP 侧，服务端与网页端零改动**。

### 这一版的改法

| | 改动 |
|---|---|
| 摊平 | 把分组结构摊成**一维行列表**（分组头行 + 任务行，折叠的组不产出任务行），交给惰性列表按需构建——**只有屏幕上看得见的卡片才会被建出来** |
| 语义不变 | 分组、全选、拖拽排序的行为完全不变（全量数据仍在内存里，只是不再全部构建成 widget） |
| 滚动位置记忆 | 惰性列表首帧的可滚动高度只是**估算值**，原来的一次性恢复会把位置夹到很靠前；改成逐帧步进，并在**用户已经自己滚动过**时立刻放弃恢复 |
| 落盘防抖 | 滚动位置的持久化加了防抖 |
| 清理 | 删掉一个从未实现的「加载更多」空壳 |

两处顺带修的都值得展开一句：

- **「点了下折叠，列表自己乱跳」**就是恢复逻辑没有让位造成的——用户手动滚动的意图必须压过程序的恢复意图，否则两者会打架。
- **滚动位置原来是每收到一次滚动通知就写一次本地存储**，一次快速滑动能打出几百次写。这本身就是卡顿的来源之一，属于「为了记住位置反而让滚动变卡」。
- 那个「加载更多」空壳没有任何实现，但它的存在会让人（包括读代码的人）误以为增量加载已经做好了。

### 为什么不做增量分页

分组下拉项、全选、拖拽排序**全部建立在「所有任务都在内存里」这个前提上**。改成增量分页会连锁出三个问题，而第三个不是显示问题：

| 功能 | 改成分页之后 |
|---|---|
| 分组下拉项 | 残缺——只列得出已加载任务所属的分组 |
| 全选 | 退化成「只全选已加载的」，而按钮上写的是「全选」 |
| 拖拽排序 | **排序保存会按当前列表顺序，把未加载任务的排序写坏** |

第三条是**数据损坏**，不是显示瑕疵。虚拟化能在不碰这个前提的情况下解决卡顿，所以本版选它。

## 配套的 APP 版本

本版**有** APP 侧改动（任务页虚拟化渲染 + 滚动位置记忆），需要配套 `v1.3.3`。

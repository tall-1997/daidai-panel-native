# 可行性分析

## 目标定义

安装 App 后，用户无需准备服务器、Docker 或独立后端，即可完成首次初始化并进入本地面板。App 负责本地服务生命周期、数据、运行时、升级、备份和故障恢复。

## 已有基础

### App 侧

- 已具备认证、Dashboard、任务、日志、环境变量、脚本、订阅、通知、依赖、用户、安全、系统和 Open API 页面。
- 已具备 Token 刷新、SSE、文件上传下载、本地通知和路由守卫。
- 当前网络层支持切换服务器地址，可将本地服务作为受管服务器接入。

### 后端侧

- Go 后端使用纯 Go SQLite 实现，适合交叉编译和嵌入式发行。
- 后端可直接托管 API 与 Web 静态资源，核心服务无需 Nginx。
- 数据集中在 SQLite、脚本、日志、依赖和备份目录。
- Android Root 方案已经证明 ARM64 与 x86_64 环境可运行后端及 Linux 脚本运行时。

## Android 可行性

### 普通 Android

可实现：

- 将 Go 后端编译为 Android 原生库，或将其改造成由 App 启动的受管本地服务。
- 服务绑定 `127.0.0.1` 动态端口，Flutter 继续通过现有 HTTP API 与 SSE 通信。
- SQLite、脚本、日志、备份存放在 App 私有目录。
- 使用前台服务承载用户明确启用的持续任务，并显示常驻通知。
- 使用 WorkManager 恢复周期检查、补偿调度和升级后的服务恢复。
- 内嵌受控 Python、Node.js 和 Git 运行时资产。

主要约束：

- Android Doze、待机限制和厂商后台策略会影响长期精确定时。
- App 私有目录中的可执行文件受 Android 版本、SELinux 和目标 SDK 策略影响。
- 依赖中含原生扩展时，需要匹配 Android ABI，常规桌面 wheel 或 npm 原生模块无法直接复用。
- Shell 能力以 Android 用户空间命令为边界，Linux 包管理能力由内嵌用户空间提供。

### Root Android

可实现：

- 复用上游 Magisk 方案的 Linux 根文件系统、Python、Node.js、Git 和包管理能力。
- 通过 App 管理模块安装、状态、端口、日志、启动和升级。
- 提供接近 Docker 版的脚本兼容性与后台常驻能力。

该档位最接近“后端全部功能本机化”。

## iOS 可行性

可实现：

- 将后端业务核心改造成进程内库，通过 Dart FFI、Platform Channel 或本地内存 API 调用。
- 在 App 沙箱保存 SQLite、脚本、日志和备份。
- 提供任务、环境变量、脚本编辑、日志、通知配置、用户、安全和备份等管理能力。
- 使用 BGTaskScheduler 执行系统分配的后台维护任务。
- 使用本地通知呈现任务结果。

平台边界：

- iOS 对下载后执行代码、通用解释器和 JIT 有严格限制。
- App 进入后台后可执行时间有限，Cron 无法保证分钟级持续精确运行。
- App Store 分发模式下，任意 Python、Node.js、Shell、Go 脚本执行无法作为完整承诺。
- 本地 HTTP 服务的后台可用性受系统挂起机制影响。

推荐定位：

- iOS 沙箱版提供本地管理核心和系统允许的自动化。
- 完整脚本执行通过用户自有远程面板或受管执行节点完成。
- 企业签名、侧载和研究版可单独评估更宽松的执行能力，产品主线仍以公开分发规则为基线。

## 关键技术决策

### 后端集成方式

| 方案 | Android | iOS | 评价 |
|---|---:|---:|---|
| 独立可执行 Sidecar | 适合 | 受限 | Android 原型最快，iOS 后台稳定性弱 |
| Go Mobile 原生库 | 适合 | 适合 | 共享业务核心的长期推荐方案 |
| Dart 重写后端 | 可用 | 可用 | 与 Flutter 集成自然，重写成本和回归风险高 |
| 内嵌 WebView 全栈 | 可用 | 可用 | 可复用 Web UI，当前原生 Flutter UI价值降低 |

推荐采用两阶段方案：Android MVP 使用受管本地服务快速验证，长期将调度、数据库、认证和配置抽成可嵌入共享核心。

## 可行性结论

- Android 普通版具备产品化条件，首要风险是后台调度和运行时兼容。
- Android Root 版具备完整能力基础，可复用上游 Magisk 资产。
- iOS 具备本地管理型面板条件，完整通用脚本执行适合采用远程执行架构。
- 产品应使用能力分级和运行时诊断向用户展示当前设备可用能力。

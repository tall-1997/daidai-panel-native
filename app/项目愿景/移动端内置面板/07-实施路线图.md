# 实施路线图

## 总体策略

先验证 Android 本地闭环，再抽取共享核心并扩展 iOS。每个阶段都形成可安装、可迁移、可回滚的产物。

## Phase 0：技术验证

目标：证明本地核心能在 Android App 生命周期内稳定运行。

- 编译最小 Go Core for Android ARM64。
- 创建本地实例并完成健康检查。
- Flutter 通过本地适配器完成管理员初始化与登录。
- 验证 SQLite、任务 CRUD、SSE 日志和 App 重启恢复。
- 测试前台、后台、锁屏、Doze 和厂商省电模式。

退出标准：

- 连续启动 100 次无数据损坏。
- 本地核心异常退出后可恢复。
- App 与本地核心版本信息可诊断。

## Phase 1：Android 本地管理 MVP

- 内置任务、日志、环境变量、脚本和备份。
- 本地实例自动初始化和服务器切换。
- Foreground Service 与运行状态通知。
- 数据目录、配额、备份和恢复。
- App 与核心协同升级。

退出标准：管理功能主链路通过自动化和真机验证。

## Phase 2：Android 受控执行

- Python 3.12 ARM64 运行时。
- Node.js 与 TypeScript 运行时。
- 受控 Shell 工具集。
- HTTPS 与 SSH Git 订阅。
- pip/npm 依赖管理和运行时组件中心。
- 任务超时、停止、并发和进程树回收。

退出标准：示例 Python、Node、Shell 和 TypeScript 任务可安装依赖、定时执行并生成日志。

## Phase 3：Android 稳定调度

- 前台服务调度。
- WorkManager 恢复和错过任务补偿。
- 开机恢复提示与电池优化引导。
- 低电量、过热和低空间保护。
- 厂商 ROM 兼容测试矩阵。

退出标准：主流 Android 版本完成 7 天持续运行测试。

## Phase 4：Root Android 完整版

- 复用 Magisk Linux 运行环境。
- App 管理模块状态、安装、端口和更新。
- Python、Node、Shell、TypeScript、Go 和包管理能力对齐。
- 普通版与 Root 版数据迁移。

退出标准：后端执行功能矩阵达到 A 或 B 级。

## Phase 5：共享核心与 iOS 本地管理

- 将数据库、认证、任务、配置和备份抽成可嵌入 Go Library。
- iOS 集成进程内核心。
- 本地数据管理、任务配置、日志与通知。
- BGTaskScheduler 维护任务。
- 远程执行节点协议。

退出标准：iOS 可离线管理本地面板数据，并通过远程节点运行完整任务。

## Phase 6：混合执行与多设备

- 执行节点注册、授权和撤销。
- 任务级执行策略。
- 节点能力协商和故障转移。
- 日志流、停止、重试和结果同步。
- 本地与远程实例统一切换体验。

## 测试矩阵

### Android

- Android 10、12、14、15。
- ARM64 首发，x86_64 用于模拟器和开发验证。
- 原生 Android、Samsung、Xiaomi、OPPO、vivo 代表设备。
- 普通、Doze、锁屏、断网、低电量、低存储和升级场景。

### iOS

- 当前支持的最低 iOS 版本与最新稳定版。
- 前台、后台挂起、系统终止和 BGTask 恢复。
- Files 导入导出、Keychain、备份与恢复。
- 远程节点断线、重连和任务幂等。

## 发布门禁

- 数据迁移和回滚测试通过。
- App 与核心版本兼容矩阵通过。
- 运行时资产摘要与签名通过。
- 无 Token、私钥和环境变量值进入日志或诊断包。
- Android 24 小时与 7 天稳定性测试通过。
- iOS App Store 规则审查项完成确认。
